# 個資盤點與隱私權政策要點

> 2026-09-04 建立。來源：`information_schema` 實查，不是憑印象列的。
>
> ⚠ **這不是隱私權政策本身，是寫政策之前的盤點。**
> 我不是律師，**條文要人審**。但「你到底收了哪些個資」這件事
> 只有查資料庫才知道，而**政策寫得對不對完全取決於這份清單完不完整**。
>
> 🔴 上線清單第 ⑦ 項。它**完全不依賴任何功能**，所以是八項裡
> 最早就能做完的一項 —— 而它是**法規要求**不是 LINE 的要求。

---

## 一、你實際收了什麼（`members` 44 欄，逐欄分類）

### 🔴 直接識別個人

| 欄位 | 從哪來 | 備註 |
|---|---|---|
| `line_user_id` | LINE 授權 | 🔴 **per-Provider 的永久識別碼** |
| `phone` ／ `phone_verified_at` | 客人填 ＋ 簡訊驗證 | 可直接聯絡 |
| `display_name` | 客人填 | 暱稱，非真實姓名 |
| `avatar_url` ／ `avatar_photo_path` | LINE 頭像／自己上傳 | 🔴 **自己上傳的可能是真實臉孔** |

### 🟡 個人屬性（行銷側寫用）

`gender`、`birthday`、`occupation`、`district`、`acquisition_source`、
`home_store_id`、`about`、`sched`、`style`

⚠ `birthday` 是**生日招待**的依據，不是可有可無的欄位 ——
政策要說清楚「不提供的影響」（個資法第 8 條第 6 款要求告知）。

### 🟡 行為與消費

`last_visit_at`、`visit_count`、`lifecycle`、`last_app_active_at`、
`tier`、`rating`、`rating_games`、`rank`、`likes_count`
＋ 另外幾張表：`orders` / `order_items` / `wallet_txns` / `topup_orders`
（**買了什麼、花多少、什麼時間在店裡**）、`app_events`（每一次點擊）

### 🔴 發票（法規強制保存）

`inv_type`、`inv_carrier`、`inv_donate_code`、`inv_tax_id`、`inv_title`
⚠ 這一組的**保留期限不由你決定** —— 稅法有規定，
所以「刪除權」對它是**有法定例外**的。政策要寫。

## 二、🔴 最容易漏掉的一項：店員備註

```
member_interactions.note   ← 店員手寫的內容
```

🔴 **客人完全不知道這個東西存在**，而《個人資料保護法》第 3 條給當事人
**查閱權與複製權**，且**不得預先拋棄**。

⚠ 也就是說：客人來信要求查閱他的個資，**店員備註在範圍內**。
→ 兩個實際後果：
- **政策要把它列進「個人資料之類別」**，不能只寫「消費紀錄」
- 🎯 **店員教育訓練要講**：那一欄寫的東西，有一天可能會被當事人看到。
  寫「客訴過冷氣太冷」沒問題，寫評價性的字眼會出事。

### 同一族的還有一個（尚未實作，但設計已定）

`member_availability` 的 `source='inferred'` —— **系統推斷的常來時段**。
CLAUDE.md 待辦 26 拍板「**A 行為推斷不對客人顯示，連他本人都不行**」，
理由是「測量行為本身會改變行為」。

⚠ 🔴 **那個決定與個資法的查閱權有潛在衝突**：
「不主動顯示」沒問題，但「當事人要求查閱時不給」不行。
→ M3 做推斷引擎時要一起想清楚，**不是做完才補**。

## 三、資料流到哪裡（個資法第 8 條第 4 款：利用之地區、對象）

| 對象 | 什麼資料 | 🔴 跨境？ |
|---|---|---|
| **Supabase** | 全部 | 🔴 **要確認專案 region** —— 若在新加坡/美國就是**跨境傳輸**，必須告知 |
| **LINE**（LY Corporation） | 授權時取得 `sub` / `picture` | 日本 |
| **簡訊商**（MAAC Go／漸強實驗室） | 🔴 **手機號碼** | 台灣 |
| **Cloudflare Pages** | 連線 IP、User-Agent（CDN log） | 全球節點 |
| **電子發票加值中心** | 發票資訊（待辦 13，還沒接） | 台灣 |
| GA4 / Meta | ⏳ **還沒開**（`toGA4` / `toMeta` 都是 false） | 🔴 開之前政策要先改 |

🎯 **最後一列是順序問題**：GA4 一開就是把行為資料送給 Google，
而政策沒寫的話那一刻就違規。→ **政策要先於 GA4**。

## 四、政策必須涵蓋的六項（個資法第 8 條，法定告知事項）

```
① 蒐集者名稱          ← 你的公司登記名稱（不是品牌名）
② 蒐集之目的          ← 會員服務／配桌／點數／發票／行銷
③ 個人資料之類別      ← 上面第一節那張表，含**店員備註**
④ 利用之期間、地區、對象、方式  ← 上面第三節，含**跨境**
⑤ 當事人得行使之權利  ← 查閱／複製／補充更正／停止蒐集處理利用／刪除
⑥ 不提供的影響        ← 例：不填生日就收不到生日招待
```

⚠ ⑤ 要**寫得出怎麼行使** —— 一個信箱或一個頁面。
🔴 **寫「請洽門市」不夠**：法定回應期限是 15 日（得延長 15 日），
而門市店員不會知道這件事。→ 需要一個**真的有人看的信箱**。

3. 寫政策 → **找人審**
4. 放上 `app.migi.tw/privacy`，接上 `profile.jsx` 那兩列
5. 填進 LINE Login channel 的 Privacy policy URL

⚠ **第 1 項只有你答得出來**，而它卡住其餘四項。
