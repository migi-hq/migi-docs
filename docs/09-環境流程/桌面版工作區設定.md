# Claude Code 桌面版工作區設定（MIGI）

> 這是什麼：MIGI 在 Claude Code 桌面版的工作區結構、開 session 的方式，
> 以及幾個容易卡住的操作點。
> 什麼時候讀：換電腦重建環境、新增第三個專案、或忘記某個面板怎麼開的時候。

## 工作區結構

母資料夾與樂活併排放在桌面，命名對齊以便在側邊欄辨識：

```
C:\Users\user\Desktop\
├─ lohas github\        ← 樂活眼鏡（既有）
└─ migi github\         ← MIGI，Claude Code 的 project folder 選這層
   ├─ CLAUDE.md         ← 常駐脈絡，每次 session 自動載入
   ├─ .claude\          ← 第一次執行時自動產生，不用手建
   ├─ migi-pos\         ← migi-hq/migi-pos
   ├─ migi-web\         ← migi-hq/migi-web
   ├─ migi-admin\       ← migi-hq/migi-admin
   ├─ sql\
   │  ├─ applied\       ← 已在 Supabase Dashboard 跑過的
   │  └─ pending\       ← 寫好還沒跑的
   └─ docs\             ← 權威文件、資料庫快照、本檔
```

## 為什麼三個 repo 共用一個 project folder

樂活與 MIGI 是兩個不相干的事業，規則會打架（樂活有「連結一律用
www.lohasglasses.com」這種專屬規矩），所以分成兩個 project folder。

但 `migi-pos` / `migi-web` / `migi-admin` 是同一套系統的三個前端，
共用同一個 Supabase 專案、同一套資料表、同一套業務規則。
改一張表三邊都要跟著調，放在同一個 project folder 才看得到彼此。

`CLAUDE.md` 的載入規則剛好配合這件事：母資料夾根目錄那份每次都載入，
子資料夾裡的只有在動到該子目錄的檔案時才載入。所以共通規矩放根目錄，
等 POS / App / 後台各自的細節多起來，再往
`migi-pos\CLAUDE.md`、`migi-web\CLAUDE.md` 放專屬規則。

## 開 session

提示框上方那排 chip 就是設定區：

- `Local` = 在本機跑（相對於 Cloud / SSH）
- 旁邊那個資料夾 chip = **project folder 選擇器**，點文字本身可以更換。
  更右邊那個獨立的資料夾圖示是「再加一個資料夾」，本機 session 用不到，
  誤按會變成同時掛兩個專案，規則會混在一起。
- 右下角是模型與權限模式

第一次指向新資料夾會跳 **Trust this workspace?**，授權範圍就是該資料夾本身。

session 建立後左側邊欄會出現對應的專案群組。多個專案就是多個 session
並存在側邊欄，點來點去切換，不是同一畫面同時掛多個資料夾。

## 權限模式

維持 **Accept edits**：檔案編輯自動套用，但執行終端機指令仍會逐次詢問。

- 改全域設定的指令（`git config --global` 這類）**不要按 Always allow**，
  每次讓它問一下比較安全
- 唯讀查詢（列目錄、讀設定、`git log`）按 Allow once 即可

## 內建終端機

有些操作在 Claude 的 Bash 工具裡做不到——它跑在非互動 shell，`stdin` 接 null，
凡是需要彈出視窗的（GCM 登入、任何互動式提示）都會失敗，
錯誤訊息是 `Cannot prompt because user interactivity has been disabled`。

這種時候用內建終端機，它是真正的互動式終端機，開在 session 的工作目錄：

- 快捷鍵 **Ctrl + `**（中文輸入法狀態下常吃不到，先切英數）
- 或點右上角工具列那排圖示裡的 `>_`
- 注意：左上角漢堡選單裡的 View 是應用程式選單（縮放、分頁），**不是**這個

實在開不出來就用 PowerShell，效果一樣，記得先 `cd` 到工作目錄。

## 已知限制

- 網頁版對話與桌面版檔案系統互不相通，舊對話的產出只能手動下載後放進 `docs\`
- 桌面版讀不到網頁版的記憶，`CLAUDE.md` 就是它在這邊的記憶
