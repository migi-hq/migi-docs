# 關鍵 ID 與測試帳號

**【這是什麼】** 跑 SQL、測試、串接時會反覆用到的固定 ID 速查表。
**【何時讀】** 每次要在 SQL Editor 手動測 RPC、或要指定測試帳號時。

---

## 固定 ID

| 用途 | ID | 說明 |
|---|---|---|
| **MIGI org** | `11111111-1111-1111-1111-111111111111` | 品牌組織 id，每支 RPC 的 `p_org_id` 都傳它。前端已封裝為 `MIGI_ORG_ID`（`src/lib/supabase.js`） |
| **高雄自由店 store** | `22222222-2222-2222-2222-222222222222` | 第一家真門市（原 seed 假店改內容而來） |

兩者都是 M0 seed 建立的「好記 id」，屬特例。**未來新增的 org / store 一律由 `gen_random_uuid()` 自動產生**，不要再手編。

### 隔離原則
- 測試資料**不刪除**，用 `members.is_test = true` 標記。
  原因：`wallet_txns` 有 append-only 觸發器，帳本不可刪改（實測會報錯）。
- **所有營運統計一律 `from v_real_members`**，不要 `from members`。
  排除邏輯已封裝在視圖裡，這樣不可能忘記排除。

### 前端切換
`src/lib/TestAccountSwitcher.jsx` 提供右下角浮動切換器，四帳號一鍵切換（改寫 localStorage 的 `migi_member` 後重整）。
只有目前登入 id 屬於這四個測試帳號時才顯示，真實會員看不到。
