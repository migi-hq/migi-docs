# MIGI 報表架構：世界級的分法

> 2026-11-03 建立。使用者：「世界級的報表系統應該不是一頁把各項目滑到底吧？仔細研究世界級 POS 系統，我要最完善的分法。」
> 依據兩組研究（都讀官方說明文件，讀不到的明講讀不到）：
> - **零售與餐飲 POS**：Square、Toast、Lightspeed（Restaurant／Retail）、Shopify、Clover、Revel
> - **按時段賣場地的行業**：ROLLER（娛樂場館）、Brunswick（保齡球）、Lightspeed Golf／GolfNow（高爾夫開球時段）、
>   OPERA Cloud／Mews／Cloudbeds（飯店）、Mindbody／Glofox（健身房會員）
> 指標的算法正本仍是《ERP 輕量報表規格》；第一、二批做了什麼見《報表優化_世界級對照》。這一份回答「報表要怎麼分、放在哪裡」。

---

## 一、世界級都是三層，不是一頁

| 層 | 是什麼 | 誰這樣做 |
|---|---|---|
| **① 總覽** | 一頁 4～8 個最重要的數字，各帶「比上期 ▲▼%」，點了直接進那一份報表 | Square 首頁小工具、Toast Weekly Overview（淨銷售、人事成本、來客、前 7 名商品）、Shopify 分析首頁、Mews 的 Manager report |
| **② 報表庫** | 依主題分類的報表清單，左側或上方切換 | 全部都有。Toast 分 9 類、Square 5 類、OPERA Cloud 19 群、ROLLER 8 類 |
| **③ 單一報表** | 版型固定：上方合計 → 可切換的趨勢圖 → 可選欄位的表格 → 匯出、列印 → 一路點到單筆交易 | Square Sales summary、Toast Sales Summary（17 張卡片可調順序） |

另外三件「不是報表、但每家都有」的東西：
- **全站共用的篩選列**：日期範圍、比較期間、門市、分組方式（Group by）。切到別份報表不會重設，Square 把 Group by 放側欄每份共用。
- **營業日切點是「設定」不是篩選**：Toast 凌晨 4 點、Lightspeed 05:29、Square／Clover 自訂。MIGI 是凌晨 6 點（已經是這樣算）。
- **現金對帳和銷售報表分開**：按收銀抽屜或班別產生**凍結的快照**（X＝預覽、Z＝結帳），記「應有」與「實點」、算短溢；之後的退貨作廢不會改動它（Lightspeed Register closure）。

## 二、MIGI 的完整分法

分類照 ROLLER 的八類為骨架（它是最接近的行業：按時段賣場地＋會員＋預收款），
加上高爾夫與飯店才有的「產能」一類，再加 MIGI 獨有的「配桌」一類。

```
報表
├─ 總覽
│
├─ A 每日營運
│   ├─ 每日彙總              一天的營收、開桌、來客、付款、作廢 —— LINE 日報的網頁版
│   └─ 日結對帳（交班）       收銀抽屜：應有 vs 實點、短溢、凍結快照                    ⚪ 要先有「點現金」的功能
│
├─ B 銷售
│   ├─ 銷售摘要              排成損益表：毛額 → 三種折扣 → 淨額 → 付款方式
│   ├─ 銷售趨勢              按小時／天／週／月；任選兩段期間比較
│   ├─ 品項銷售              商品、類別、子類別（餐飲的 PMIX）；毛利欄等商品成本有填
│   └─ 折扣與優惠            會員等級、優惠券、商人熊、暢打抵掉的檯費
│
├─ C 收款與預收
│   ├─ 付款方式              現金、刷卡、LINE Pay、點數
│   ├─ 錢包滾動表            期初餘額 ＋ 儲值 ＋ 贈點 − 用掉 ＝ 期末（本金／贈點分開）   ← ROLLER Deferred Revenue、Mews Deposit Ledger
│   └─ 收入認列              「收到的錢」vs「賺到的錢」：儲值、暢打                   ← ROLLER Revenue Recognition
│
├─ D 桌與產能（命脈）
│   ├─ 產能總覽              上座率、調整後上座率（扣保留、維修的桌）、每桌時營收、每場平均  ← 飯店 RevPAR／高爾夫 RevPATT
│   ├─ 時段熱度              星期 × 小時 使用率                                      ← Mews Activity、Mindbody 尖離峰
│   ├─ 每一桌                使用率排名；桌況時間分配：使用中／預留中／空著／維修        ← Brunswick 球道使用報表
│   └─ 收桌與翻桌            收桌延遲、翻桌間隔
│
├─ E 配桌與預約（MIGI 獨有）
│   ├─ 配桌漏斗              開房 → 湊滿 → 入座 → 遲到分鐘 → 沒來                      ← ROLLER Session Punctuality
│   ├─ 沒湊滿的需求          依時段、級距、玩法：誰想打但沒開成                         ← 飯店「被拒絕的需求」
│   └─ 包桌預約              預約 vs 實際到場、沒來、取消
│
├─ F 客人與會員
│   ├─ 來客                  人次、新舊客、來店頻率分布
│   ├─ 新客回訪              第一場之後有沒有第二場；依第一次來那一週、依來源         ← Mindbody First Visit
│   ├─ 沒再回來名單          打過、之後 N 天沒來，排除已經報名下一場的人 —— 直接拿去關心  ← Mindbody No Return
│   ├─ 會員淨增減            新註冊、升等、流失放同一張                                ← Glofox Member Movement
│   ├─ 會員等級與段位        各等級、段位的人數、來店、營收
│   └─ 客人終身價值          來過幾位、平均來幾天、平均每位付多少
│
├─ G 會員來源
│   └─ 來源漏斗              各來源、管道與活動、帶最多人來的會員
│
├─ H 員工
│   ├─ 店員業績              配桌數、帶新、綁定客人來店
│   ├─ 店員稽核              每人的折扣、作廢、取消開桌、收桌延遲                      ← ROLLER 營運類、Toast Cash & Loss
│   └─ 工時與獎金            打卡、排班、獎金試算                                     ⚪ 要等打卡（待辦 47）
│
├─ I 例外與損失
│   └─ 作廢、取消、退款、改價  依時間與人；原始紀錄點得進去
│
├─ J 會計
│   └─ 會計匯出              依天、依門市、依法人；發票                               ⚪ 發票還沒串接
│
└─ K 多店比較
    └─ 門市並排              同一組指標各店並排                                       ⏳ 第二間店營運才有意義

設定（不放在報表裡）
├─ 報表目標                  各店每月營收目標、兩平上座率（已有）
├─ 時段班別                  自訂「早／午／晚／深夜」幾點到幾點                         ← Lightspeed 報表班別
├─ LINE 日報                 收件人、要放哪幾段（照 Toast 的 Z 報表段落勾選）
└─ 桌的狀態                  維修、保留的時間（產能才算得出「調整後上座率」）           ⚪ 目前沒有記
```

### 總覽放哪 8 格（每格都帶比較、點了進報表）
| 格 | 進到 |
|---|---|
| 營收 | B 銷售摘要 |
| 每桌時營收 | D 產能總覽 |
| 上座率（對照兩平線） | D 產能總覽 |
| 開桌數 | D 每一桌 |
| 配桌成桌率 | E 配桌漏斗 |
| 來客人次 | F 來客 |
| 新客 ＋ 回訪率 | F 新客回訪 |
| 本月營收對目標 | B 銷售趨勢 |
比較預設：查一天比上週同一天、查多天比前一段同樣長度；可另選「去年同期」（Toast、GolfNow 都有年對年）。

### 單一報表的版型（每一份都一樣）
```
標題 ＋ 一句話說明這份報表回答什麼
上方 3～5 個合計（各帶比較）
趨勢圖（可切 天／週／月）
表格（可排序、可選欄位、匯出 CSV）
每一列點得進去 → 原始紀錄（場次、訂單、會員）
```
數字旁邊一個「ⓘ」點了顯示算法（Square 是滑過顯示；後台也要能在平板上用，所以用點的）。

## 三、刻意不做的（硬規則 5.5、5.7）

| 世界級有的 | 為什麼 MIGI 不做 |
|---|---|
| 自訂報表產生器（Shopify ShopifyQL、Square Custom Report Builder、Lightspeed Analytics） | 要有人維護一套查詢語言與無數自訂報表；七間店的需求用固定報表＋匯出 CSV 就夠 |
| 寄到 Webhook／S3／SFTP（Lightspeed Insights） | 沒有接收的系統 |
| 每小時更新的儀表板（Toast） | 後台是「要看才打開」，打開時現算就是最新的 |
| AI 自動洞察（Shopify、Mindbody） | 資料量還不夠；先把固定報表做對 |

## 四、分批

| 批 | 內容 | 要動什麼 |
|---|---|---|
| **一** | 拆成報表庫：總覽 ＋ 左側分類清單 ＋ 統一版型 ＋ 篩選列寫進網址；現有的數字搬進對應的報表 | 前端為主；後端補「每天的走勢」（上座率、來客） |
| **二** | 用現有資料新做的報表：錢包滾動表、會員淨增減、沒再回來名單、包桌預約、店員稽核、配桌遲到與沒來、時段班別設定、日報段落勾選 | 後端各補一段查詢 |
| **三** | 要先有新功能才做得出來：日結對帳（點現金）、桌的維修保留紀錄、工時與獎金、發票、門市比較 | 各自是一個功能 |

📌 待查證的一件事：Shopify 能不能原生排程寄報表，兩組來源說法不一，跟 MIGI 無關，不追。
