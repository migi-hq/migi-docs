## 二、帳務基礎

- [ ] 找一位**記帳士/會計師**(開店前就找,不要等出事)— 台灣小公司通常委外記帳,月費幾千元
- [ ] 建立**收支記帳習慣**:每筆支出留憑證(發票/收據/信用卡帳單截圖)
- [ ] 區分「公司的錢」與「個人的錢」— 絕不混用(投資人/稅務最在意這個)
- [ ] 決定發票方式(電子發票)— POS 開立發票需串接**電子發票加值中心**(SaaS)

## 三、各項服務怎麼付款報帳

| 服務 | 能開台灣統編發票? | 付款 | 報帳方式 |
|---|---|---|---|
| 網域(Gandi/戰國策) | ✅ 可 | 公司卡 | 要統編發票 |
| Google Workspace | ⚠️ 直刷是國外發票;要統編需透過台灣代理商 | 公司卡 | 視是否需統編決定走代理商 |
| Cloudflare(Pages/DNS) | ❌ 國外無統編 | 公司卡 | 信用卡帳單當憑證,列國外費用 |
| Supabase(後端) | ❌ 國外無統編 | 公司卡 | 同上 |
| GitHub | ❌ 國外 | 公司卡 | 同上(初期免費) |

**原則:**
- [ ] 有公司後,以上**全部刷公司卡**
- [ ] 能開統編的(台灣網域商)→ 要統編發票
- [ ] 國外服務開不了統編是**正常的** → 留信用卡帳單,會計師會列國外費用,別擔心

## 五、品牌信箱規劃(用品牌信箱,不用個人信箱)

### 命名原則(參考跨國企業)
- **對外用「功能信箱」**(info/partner/pr)、**對內用「人名」**(jim)、**系統用 no-reply**
- 功能信箱綁「職能」不綁人 → 離職換人不用改,資產屬於品牌
- Google Workspace 中,功能信箱可設成**別名/群組**(轉到主信箱),**不佔授權額度、幾乎零成本** → 不用急著全開

### 現在就開(開店前必要 4 個)
### 啟動順序（雞生蛋:設公司信箱前要先有個信箱去註冊網域商）

世界大廠/新創都這樣解 — 用個人信箱啟動,有了網域開公司信箱後,把後台帳號「轉正」到公司信箱。註冊網域商用個人信箱是後台行為,沒人看得到,不影響專業度;只有「對外溝通/對外註冊」一定要用公司信箱。

- [ ] **開一個專用 Gmail** 當過渡信箱(如 `migi.founder@gmail.com`),不要用平常塞滿垃圾信的私人信箱 → 網域/帳務通知不被淹沒,日後好交接
- [ ] 用這個 Gmail 註冊**網域商**(建議 Gandi)、買下網域(`migi.tw` 等)
- [ ] 有了網域 → 開公司信箱 `admin@`、`info@`…
- [ ] **回頭把網域商帳號的聯絡/登入信箱改成 `admin@migi.tw`**(轉正,不再綁個人 Gmail)
- [ ] 之後**所有平台**(Supabase/Cloudflare/LINE…)一律用 `admin@` 註冊
- [ ] 過渡 Gmail 留著當緊急復原備用,但不再當主力

> 原則:個人信箱只是「啟動的鑰匙」,用完功成身退;真正的帳號鑰匙圈最後落在 `admin@`(綁職能不綁人,開 2FA)。

🔴 **2026-09-04 更正網域：一律 `migi.tw`，不是 `migi.com.tw`。**
這一節原本兩個網域混用（上面第 78／80 行寫 `migi.tw`，下面這幾行寫
`migi.com.tw`）—— 而**實際在用的是 `migi.tw`**：
`admin@migi.tw` 已經是 GitHub 的 **Primary 且已驗證**信箱、
Supabase Auth 的唯一帳號（2026-07-12 建立並登入過）、以及 Git 的 commit 身分。
⚠ 這種矛盾很危險：照著下面開了 `@migi.com.tw`，就會有**兩套信箱**，
而既有平台帳號全綁在 `@migi.tw` 上 —— 那不會報錯，只會愈來愈亂。

### 🔴 三種東西不一樣,搞混會多花錢或多開沒人看的信箱

| | 誰收得到 | **誰能登入** | 費用 |
|---|---|---|---|
| **別名** alias | 主帳號的人 | 🔴 **沒有人**(它不是帳號,沒有密碼) | 免費 |
| **群組** group | 群組成員(多人) | 沒有人 | 免費 |
| **帳號** user | 那個人 | ✅ 那個人 | **每人每月要錢** |

🎯 **判準:有沒有一個人要「專門進去看那個信箱」?**
· 沒有 → **別名**(信進 `admin@`)　← **今天全部都是這個**
· 有一群人要一起看 → **群組**(例如日後的 `service@` 給客服三個人)
· 那個人要用那個身分**登入、存檔案、開會** → 才需要**帳號**

⇒ 「每個部門一個地址」**不等於**「每個部門一個付費帳號」。

🔴 **而 Google Workspace 帳號跟 migi-admin 的登入是兩件事** ——
部門的人日後要進後台改資料,靠的是 `auth.users` ＋ `staff` 一列,
**跟信箱完全無關**(可以同 email 也可以不是)。

### 🎯 最重要的原則:先有那件事在發生,才開那個地址

**開了沒人看的信箱比沒有更糟** —— 客人寄了信沒人回。

### 第 0 層:現在就開(一個人的規模)
- [x] 先辦 **Google Workspace**(`migi.tw` 信箱)　✅ **2026-09-04 確認已有**
- [x] **`admin@migi.tw`** — 註冊一切平台帳號的鑰匙圈(LINE/IG/Supabase…) ✅ **已在用**
      🔴 **不對外**,原因見下面 `privacy@` 那一項
- [ ] **`info@migi.tw`** — 對外總機:官網、名片、IG bio、**Google 商家**
- [ ] **`no-reply@migi.tw`** — 系統自動信(App 通知、驗證碼、發票)**只發不收**
- [ ] 🔴 ~~**`jim@migi.tw`** — 你個人信箱~~
      → **一個人的時候不要開**:`admin@` 就是你,
        多一個只是多一個要記得看的地方。**有第二個員工再說。**
- [ ] 🔴 **`privacy@migi.tw`** — **`admin@` 的別名**。隱私權政策上要印的就是它。
      ✅ **不用買、不用開新帳號、不佔授權額度**(一個帳號最多 30 個別名)。
      ```
      admin.google.com → 目錄 → 使用者 → admin@migi.tw
        → 使用者資訊 → 「別名電子郵件地址」→ 新增 → 儲存
      ```
      ⚠ 生效通常幾分鐘(官方說最多 24 小時)—— **設完寄一封測試信確認**。

      理由見 `docs/09-環境流程/個資盤點與隱私權政策要點.md`,最硬的一條是:
      🔴 **`admin@` 是註冊所有平台的鑰匙圈**(LINE/Supabase/Cloudflare/GitHub),
      印在公開政策上等於告訴別人「這個地址值得攻擊」。
      其次:個資法查閱請求有 **15 日**期限,而 `admin@` 會被各種通知淹沒;
      以及**政策上印的地址日後極難改**(名片、官網、App 內、已公告的政策本文)。

### 第 1 層:開店後才開(有客人、有店員)

**每一個都要寫得出「什麼事件觸發它」,寫不出來就不要開。**

- [ ] **`billing@migi.tw`** — 帳務
      🎯 觸發事件:**接電子發票加值中心那天**(CLAUDE.md 待辦 13)。
      🔴 理由是**有一台機器要寄信給它**(系統通知、字軌用罄警告),
        不是「公司都有財務部」。日後加盟拆帳、對帳也走它。
- [ ] **`service@migi.tw`** — 客服(會員問題、點數爭議)
      🎯 觸發事件:**有人要回客服信**那天 → 開成**群組**(多人共收)。
      ⚠ 在那之前客人的問題走 `info@`,而 `info@` 是你在看。
- [ ] **`jobs@migi.tw`** — 徵才
      🎯 觸發事件:**開始徵人**那天。

### 第 2 層:展店/加盟才開
- [ ] **`partner@migi.tw`** — 加盟/聯名/系統授權洽談(IP 事業特別需要)
- [ ] **`pr@migi.tw`** — 媒體公關(賽事/明星曝光,記者習慣找 pr@)
- [ ] **`vendor@migi.tw`** — 供應商/採購

### 🔴 明列「不要開」的(不是漏掉,是決定)

| | 為什麼不開 |
|---|---|
| **採購** `purchase@` | 飲料、零食、桌椅耗材的供應商在台灣**多半用 LINE 或電話**,不會寄 email 給你。真的有 email 往來時再開 `vendor@` |
| **企劃/行銷** `marketing@` | **內部職能不需要對外地址**。對外用 `info@`,對媒體用 `pr@` |
| **營運** `operations@` | 同上 —— 沒有外部的人會寄信給「營運部」 |
| 每個部門各一個 | 🔴 那是**有那個部門**才開。一個人的公司開八個信箱,結果是八個都沒人看 |

🎯 **通則:對外才需要地址,內部職能不需要。**
`billing@` 之所以是例外,是因為它有一台**機器**要寄信給它。

### 品牌帳號註冊
- [ ] 用 `admin@` 註冊以下**全部**(不要用私人 Gmail):
  - [ ] LINE 官方帳號(設多人管理,擁有者永遠是品牌信箱)
  - [ ] Instagram / Threads / Facebook(`@migi.play` 等名稱先搶卡位)
  - [ ] Cloudflare / Supabase / GitHub
  - [ ] 網域註冊商帳號
- [ ] 品牌主信箱**開兩步驟驗證(2FA)**,密碼+備援碼存進密碼管理器(Bitwarden/1Password)

## 六、法規盤點(風險最高,務必找專業)

> 這塊是 MIGI 最該優先釐清、又最容易被忽略的。**一定要諮詢律師/會計師。**

- [ ] **點數/儲值的法遵**:預付儲值在台灣可能涉及「**商品(服務)禮券**」相關規範(履約保證、不得設使用期限等)— **問律師/會計師**,這直接影響你的點數系統設計
- [ ] **麻將館的營業登記/特許**:確認營業項目、地方政府規範(電子遊戲場?休閒娛樂?)— **問當地主管機關/律師**
- [ ] **博弈紅線**:你「全程點數、桌面不見現金、不對賭」的設計就是為了避開賭博罪 — 請律師確認你的營運模式安全
- [ ] **個資法**:會員資料、牌譜資料的蒐集要有告知+同意(會員條款)— 請律師擬條款
- [ ] **食品/餐飲**:餐飲吧要有食品業登記、相關衛生規範

## 七、建議執行順序

```
1. 諮詢會計師/律師(公司型態、營業項目、點數法規、博弈紅線)
         ↓
2. 成立公司 → 拿統編 → 開公司帳戶 + 公司卡
         ↓
3. 辦 Google Workspace → 開 info@ / admin@ / jim@ 信箱
         ↓
4. 買網域(migi.tw / migi.app,公司卡+發票)→ DNS 轉 Cloudflare
         ↓
5. 用 admin@ 註冊一切平台帳號 + 開 2FA
         ↓
6. 找記帳士、建立記帳習慣
```
