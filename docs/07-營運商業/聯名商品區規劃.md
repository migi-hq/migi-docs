# MIGI 咪吉麻將 — 聯名商品區規劃 v0.2

> 核心定位：聯名商品區 ≠ 賣場角落，而是 **實體變現出口 + 打卡點 + 段位炫耀牆** 三合一。
> 目標體驗：一進門就想拍 → 拍了就想買 → 買了還想升段位買更好的。
>
> ## 🔴 v0.2（2026-09-08）：拿掉商品清單，修掉一個會壞的欄位設計
>
> **① 商品清單整段移除，改指向《首店周邊商品規劃》。**
> 原 §3.5 列了約 30 個品項與上市優先序，而《首店周邊商品規劃》（2026-08-29）
> 也有一份 —— **兩份已經打架**：
> ```
> 小熊娃娃   這份寫「第一波」   ／ 周邊那份排「第三批（半年後）」
>            理由：MOQ 數百隻、絨毛要開版打樣、資金門檻最高
> 牌尺       這份寫「基本款可買」／ 周邊那份「不販售，只兌換」
>            理由：只能換不能買才是身分標記，標價賣掉那個價值
> 品項總數   這份約 30 個      ／ 周邊那份 8 個，且明寫「開幕期 5 個 SKU 以內」
> ```
> 🎯 **判準是變更頻率**：品項與定價每月會動（詢價、銷售數據），
> 空間與陳列是裝修時定一次。合成一份的話，改一個售價要動到裝修文件。
> ⇒ **兩份都留著，但清單只能出現在一份裡。**
>
> **② 🔴 `min_dan` 欄位不存在 —— 而且它把兩個概念混在一起了。**
> ```
> 段位     rank_tiers    銅／銀／金／白金／鑽石／大師熊      ← 打牌打出來的
> 會員等級  member_tiers  珍奶／焦糖布丁／提拉米蘇／主廚特調  ← 消費累積出來的
> ```
> 「**金牌熊**以上才能買」是**段位**；而《首店餐飲籌備》第 10-1 節提議的
> `min_tier`（「主廚特調隱藏品項」）是**會員等級**。
> **兩份文件各命名了一個，做成同一個欄位就會壞** ——
> 症狀是「有些人看得到不該看到的商品」，而且不會報錯。
>
> **③「全程點數購買」不成立。** `order_payments.method` 是
> `cash / credit_card / line_pay`，點數走另一條（`orders.points_used`）。
> 「桌面不見現金」講的是**牌桌**，不是櫃檯。

## 1. 三重角色

| 角色 | 作用 |
|---|---|
| 零售區 | 賣商品賺錢（自有 IP 毛利最高） |
| 打卡牆 | 網美拍照 → 商品自動入鏡 → 免費宣傳 |
| 段位展示處 | 把「打得好才買得到」實體化 → 刺激消費與競技 |

---

## 2. 空間規劃

### 2.1 位置：動線必經 + 等待區
- 放在 **入口 / 結帳區 / 等待配桌區**。
- 理由：配桌候補要等 → 等待時間 = 最佳逛街時間；入口 = 進門第一眼 + 離店最後一眼雙重曝光。
- 不要藏角落。

### 2.2 分區：按「段位解鎖」分層陳列（MIGI 獨門）

| 層 | 陳列方式 | 商品 |
|---|---|---|
| 開放區 | 平台／開架，人人可買 | 小熊周邊、Tee、飲料杯、吊飾 |
| 段位解鎖區 | 玻璃櫃 + 特殊燈光 | 金牌熊以上才能買的限定款、編號牌尺 |
| 雀神專屬區 | 最頂、最稀有位置 | 當季雀神同款、限量聯名 |

- 視覺做出「越往上越稀有」層次 → 低段位客人看到買不到的，產生升段動力。
- **把競技系統變成消費引擎**。

> ⚠ **這裡列的是「哪一層放什麼類型」，不是品項清單。**
> 實際有哪些品項、MOQ 多少、什麼時候上，一律看
> 《首店周邊商品規劃》第 1、2 節。
> 📌 而**開幕當天這三層只有第一層是滿的** —— 周邊那份第一批只有五項，
> 段位解鎖款排在第二、三批。陳列設計要能接受「上面兩層先空著或少量」，
> 不然裝修完會出現兩個空櫃子。

### 2.3 打卡牆：聯名主視覺
- 一面牆 = 聯名主題大型打卡背景（小熊×聯名 IP 巨型公仔／霓虹／插畫），旁邊即商品。
- 拍照 = 商品入鏡 = 免費廣告。
- **隨聯名檔期更換** → 製造「限定、趁現在」急迫感。

⚠ **開幕期沒有聯名對象**（見 §3 的上市順序：聯名排在「品牌有名氣後」）。
⇒ 打卡牆的**第一版必須是自有 IP**（小熊），而且要能撐三到六個月。
🔴 把它設計成「等聯名檔期才有內容」的話，開幕當天那面牆是空的。

### 2.4 體驗陳列：商品可玩
- 牌尺／牌／周邊設可試用體驗台（摸材質、試手感）。
- 「欸這個好可愛你看」的互動帶動購買，契合女生聚會場景。

## 3. 聯名策略（找誰聯名）

| 類型 | 目的 |
|---|---|
| IP 聯名（三麗鷗／插畫家／卡通角色） | 借粉絲拉新客 |
| 在地聯名（高雄品牌／文創） | 地域獨特性、媒體話題 |
| 異業聯名（美妝／服飾／飲料） | 精準打女性客群 |
| 自有 IP（MIGI 小熊周邊） | 毛利最高、最該主推 |

**順序：先做滿自有 IP，聯名等品牌有籌碼再談。**
⚠ 聯名的談判籌碼是**客流與話題度**，開幕期兩者都還沒有 ——
這時去談只會拿到差的分潤與高的 MOQ。

## 3.5 商品清單 → **移到《首店周邊商品規劃》**

🔴 **本節 v0.2 整段移除**，理由見檔頭。
品項、MOQ、成本、售價、上市批次一律看
`docs/07-營運商業/首店周邊商品規劃.md`。

**這裡只留不會隨品項變動的東西 —— 商品設計三原則：**

1. **能編號的就編號**（No.001…）→ 稀缺、收藏、炫耀
2. **能綁段位／成就的就綁** → 競技變消費動力
3. **能印小熊＋麻將的就印** → 每件商品都是行走的廣告

⚠ 第 2 條要小心：**綁定要能被系統驗證**，不然它只是店員記不住的規矩。
今天系統裡可驗證的有 `members.rank`（段位）與 `member_tiers`（會員等級），
**而它們是兩個不同的東西**（見 §4）。

## 4. 與系統串接

### 🔴 段位 ≠ 會員等級 —— 這是本節 v0.2 最重要的更正

```
段位      members.rank ／ rank_tiers      銅→銀→金→白金→鑽石→大師熊
          怎麼來的：打牌的名次（rating）    會掉、每季重置
會員等級   members.tier ／ member_tiers    珍奶→焦糖布丁→提拉米蘇→主廚特調
          怎麼來的：累積消費金額           只升不降（threshold_amount 0/6,000/20,000）
```

🔴 v0.1 寫「商城 `min_dan` 欄位控制誰能買」——
**那個欄位不存在**，而且 `dan` 這個命名把兩者混在一起了。
⚠ 《首店餐飲籌備》第 10-1 節提議的 `min_tier` 是**會員等級**那一個。
**兩份文件各命名了一個概念，做成同一個欄位就會壞** ——
症狀是「有些人看得到不該看到的商品」，**而且不會報錯**。

→ 真的要做的話是**兩個獨立欄位**（或一個帶維度的條件），例如：
```
min_rank   text  null=不限   'gold' 以上才看得到     ← 段位（打出來的）
min_tier   text  null=不限   'chef_special' 才看得到  ← 會員等級（消費累積）
```
⚠ **但現在不要建。** 開幕第一批沒有任何段位解鎖商品
（周邊那份排在第二、三批），建了就是這個專案一再記錄的
「建了沒人讀」。**等第一個解鎖款真的要上架那天再做。**

### 其餘三項

- **點數結算**：點數**是付款方式之一，不是唯一**。
  🔴 v0.1 寫「全程點數購買」—— `order_payments.method` 允許
  `cash / credit_card / line_pay`，點數走 `orders.points_used`。
  「桌面不見現金」講的是**牌桌**（賭博紅線），不是櫃檯。
- **成就綁定**：部分品綁成就（如「百勝熊」才能買的編號款）。
  ⏳ 成就系統的解鎖條件目前**是前端寫死的**（`ACH` 陣列的 `on: 1`），
  後端還沒有成就主檔 —— 見 CLAUDE.md 待辦 33「獎勵頁那批」。
  **綁定要等那批做完**，不然條件無法驗證。
- **限量編號**：聯名品做流水編號（No.001…）→ 稀缺 + 收藏 + 社群炫耀。
  📌 編號**不要另建機制** —— 系統已經有 `next_doc_no(org, store, doc_type)`
  ＋ `doc_counters`（CLAUDE.md 待辦 19）。加第二套是這題最糟的結果。

## 5. 空間邏輯總結

> 聯名區放在等待動線上，用**段位分層陳列**（開放→解鎖→雀神專屬），
> 配一面**隨檔期換的打卡牆**，商品可試玩。
> → 從「賣場」升級成「會自己賣貨、自己宣傳、還刺激打牌」的複合空間。

⚠ **開幕當天這個總結只有一半成立**：第一批五個品項全在開放區，
段位解鎖與雀神專屬是空的，也還沒有聯名檔期。
🎯 **那不是問題，是順序** —— 但**裝修要按終局做**（櫃位、燈光、牆面留好），
因為那些是事後補最貴的東西（同《首店餐飲籌備》4-1 的「建好、先不裝滿」）。
