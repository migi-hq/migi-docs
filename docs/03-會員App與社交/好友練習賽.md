## 二、資料放在哪裡

### 結論：牌局本身沿用 `table_sessions`，掛在一間「虛擬門市」的「虛擬桌」上；等朋友那一段另開兩張表

```
friendly_games          一場好友練習賽（開的人、玩法、積分、最晚開打、狀態、session_id）
friendly_game_players   誰在這一場（加入、離開）
friendly_invite_links   分享出去的邀請（一場一個 token，見第四節）
stores                  每個機構一間 is_virtual = true 的「好友練習賽」門市
tables                  那間門市底下的虛擬桌，一場用一張，打完放回去重用
table_sessions.mode     多一個值 'friendly'
```

### 為什麼不另開一套表

計分板引擎有 **17 支函式**是用「這台裝置在哪一桌 → 那一桌開著的場次」找到牌局的
（`where table_id = d.table_id and status = 'open'`）。手機計分則是「這個人坐在哪一場」，
再回頭拿那一場的 `table_id`（`_tbl_device`）。

* 另開一套表 ＝ 計分板整套規則重寫一份 ⇒ 計分規則從三份變四份（後端、教學引擎、預覽，再加一份）。
* `table_sessions.store_id`／`table_id` 都是 NOT NULL；改成可空的話，上面那 17 支都要改。
* 給每一場一張真的（虛擬的）桌 ⇒ **計分板一行都不用改**，手機也照樣找得到自己那一場。

### 虛擬桌不會有平板

平板配對綁的是真的桌（`table_devices.kind = 'tablet'` 一定有 `table_id`），
而虛擬桌只在建立一場好友練習賽時由後端產生，後台的平板配對頁看不到虛擬門市 ⇒ **自然只有手機進得來**。
後端另外在平板的配對函式擋一次（虛擬門市的桌不能配平板）。

### 虛擬門市要從哪些地方藏起來

`list_stores_tx`、`admin_list_stores_tx`、`admin_list_tables_tx`、POS 選門市、會員 App 選門市、
門市詳情頁。判準一律是 `stores.is_virtual`，**不要用店名或代碼判斷**。

## 三、狀態與流程

```
friendly_games.status
  waiting   開了、在等朋友（1～3 人）
  playing   四人到齊：建好 table_session（mode = friendly）＋ 四列 session_players，等大家在手機上定座位
  finished  約定的將數打完，成績算好、虛擬桌放回去
  cancelled 開局的人取消／過了最晚開打時間還沒湊滿／打到一半沒人動（見第六節）
```

1. **開一場**：選玩法、花、將數、積分、哪一天、最晚幾點前開打、我可以打（照「我要自己開一桌」）。
   檢查互斥 → 建 `friendly_games`（waiting）＋ 自己一列 `friendly_game_players`。
2. **邀請**：
   * 「分享到 LINE 邀請朋友」：拿這一場的邀請 token，前端 `liff.shareTargetPicker` 送一張 Flex 卡片，按鈕連到 App `?f=<token>`。
   * 「＋ 邀牌咖加入」：選牌咖，發 App 內通知（不推 LINE），點了一樣走加入。
3. **加入**：打開 `?f=<token>` ⇒ 後端 `join_friendly_game_tx(token)`：
   * 成功 ⇒ 落在好友練習賽切頁，最上方跳「已加入小美的好友練習賽」
   * 失敗 ⇒「加入不了」那一頁，四種原因：已經滿了／已經取消／正在配桌或在打正式段位賽／已經在另一場好友練習賽
   * 還沒註冊 ⇒ 先註冊，註冊完自動加入（token 暫存在 localStorage，同牌咖邀請連結那一套）
4. **離開／取消**：加入的人「離開這一場」（waiting 才可以）；開局的人「取消這一場」（waiting 才可以，取消會通知已加入的人）。
5. **四人到齊**：同一個交易裡
   * 挑一張空的虛擬桌（沒有就建一張）
   * 建 `table_sessions`（mode = friendly、store = 虛擬門市、planned_rounds、game_type、flower、stake_level_id）
   * 四列 `session_players`（seat 先空著，由手機「定座位」決定）
   * `friendly_games.status = playing`
   * 四個人各收到一則 App 內通知（成桌彈窗），**不推 LINE**
6. **打牌**：四支手機打開「MIGI 智慧計分板」照現有流程定座位、記分。頂條寫「好友練習賽」。
7. **打完**：最後一將確認那一刻（既有觸發器 `trg_session_rounds_auto_score` → `_score_settle_tx`）：
   * 寫 `finish_rank`、`final_score`（好友練習賽的數據要用）
   * **不叫** `apply_session_rounds_tx`（不算段位分）、**不發成就事件**
   * 直接收桌：`table_sessions.status = completed`、`ended_at`、手機的 `bound_session_id` 照收桌的做法放掉；虛擬桌放回去
   * `friendly_games.status = finished`
   * 每人一則「好友練習賽結束」通知 ＋ LINE 推播（結算卡，沒有段位分那一行）
   * 牌局結束卡（計分板）沒有段位分那一行（`rating_delta` 本來就是 null）

## 四、邀請 token

照牌咖邀請連結那一套（`buddy_invite_links`），但**一場一個、可以用到滿**（不是一次性）：

```
friendly_invite_links(token, game_id, created_by, created_at)
```
* token 隨機 22 字元，不帶任何可猜的東西
* 有效期間 ＝ 那一場還在 waiting；滿了、取消、開打之後拿這個 token 進來一律「加入不了」並講原因
* 自己點自己的連結 ⇒ 直接落在切頁，不算加入

## 五、要改的既有函式（排除好友練習賽）

🔴 **漏一支不會報錯，只會被灌分。** 判準一律是 `table_sessions.mode = 'friendly'`。
清單是 2026-10-28 掃「函式本體提到 session_players／table_sessions／hands」的 98 支後分出來的；
動手時每一支都要撈線上全文逐支看，不可以照這份清單直接改（硬規則 3）。

| 類別 | 函式 | 怎麼改 |
|---|---|---|
| 結算 | `_score_settle_tx` | 好友練習賽：不算段位分、不發成就、打完直接收桌 |
| 結算 | `_settle_notify_on_rank`、`_push_settle_fields` | 好友練習賽換一張卡片（沒有段位分）、通知文字換「好友練習賽結束」 |
| 個人成績 | `_member_stats_core`、`_member_hand_counts`、`_member_highlight` | 排除 |
| 排行 | `_season_rank_rows_core`、`get_season_leaderboard_tx`、`_ach_season_close_events` | 排除 |
| 成績頁紀錄 | `get_my_games_tx`、`_game_row` | 排除（好友練習賽另有一支列自己的紀錄） |
| 個人卡、同桌 | `get_member_card_tx`、`_pair_history`、`list_recent_players_tx`、`member_opponents_tx` | 排除 |
| 牌咖團 | `_team_session_ids`、`_team_top_contributor`、`get_team_tx` | 排除 |
| 門市 | `_store_real_record_count`、`_member_home_store` | 排除 |
| 給同桌評價 | `like_player_tx`、`dislike_player_tx`、`check_session_blocks_tx` | 好友練習賽不做評價（結算通知不開那個抽屜） |
| 上線前隨機名次 | `placeholder_ranks_tx` | 好友練習賽一律不跑 |
| 互斥 | `_check_join_conflict` | 加掃「身上有沒有 waiting／playing 的好友練習賽」 |
| 平板配對 | 配平板的那一支 | 虛擬門市的桌不能配平板 |
| 門市清單 | `list_stores_tx`、`admin_list_stores_tx`、`admin_list_tables_tx` | 藏 `is_virtual` |

**保留、不用改的**：`_session_hands`、`get_my_game_hands_tx`（牌局回放，好友練習賽也要用）、所有 `tbl_*`（計分板）。

### 錯誤儀表加一格

「好友練習賽的玩家有沒有段位分或成就」：`mode = 'friendly'` 的 `session_players` 若 `rating_after` 或 `score_points` 有值 ⇒ 🔴。
這一格是結構性的：不管哪一支漏改，只要真的灌進去了就會紅。

## 六、自動收尾（排程）

| 情況 | 處理 |
|---|---|
| waiting 過了最晚開打時間還沒滿 | cancelled，通知已加入的人「沒有湊滿」 |
| playing 但 6 小時沒有任何一局確認 | 打完 1 將以上 ⇒ 照打完的將結算（同「提前結束」）；一將都沒打完 ⇒ voided、cancelled |

掛在既有的 pg_cron（`migi_sweep_expired` 那一支每 5 分鐘跑）旁邊再開一支，不要塞進配桌的掃描函式裡。

## 八、還沒定、照建議先做的

| | 建議 | 理由 |
|---|---|---|
| 一個人同時開幾場 | 一場 | 互斥本來就讓一個人同時只在一場裡 |
| 最晚開打時間 | 跟配桌一樣必填 | 沒有它就沒有「沒湊滿」的終點，房會一直掛著把人卡住 |
| 誰能看到這一場 | 只有拿到邀請的人 | 沒有門市，不出現在配桌列表 |
| 牌局回放 | 沿用 `get_my_game_hands_tx` | 不另寫一份 |
