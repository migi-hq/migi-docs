# MIGI 咪吉麻將 — 會員分級制度規格 v0.2

> 兩套分級刻意分開:**會員等級=消費身份**(暖、只升不降)、**段位=牌技實力**(競技、會升降)。
> 顯示名是 UI 皮,系統底層一律用數字 + 累積值/分數。介面並列顯示,例:`鬆餅會員 · 金牌熊 II`。

---

## 1. 會員等級(消費身份)

**主題:甜點　|　依據:累積消費(終身,只升不降)**

| 等級 | 顯示名 | 門檻(累積消費點數) | 約略意義 | tier 值 |
|---|---|---|---|---|
| 1 | 🥤 珍珠奶茶 | 0(註冊即是) | 入會就有,人人是會員 | basic |
| 2 | 🧇 焦糖布丁 | 滿 10,000 點 | 穩定常客(每週來約半年) | mid |
| 3 | 🍰 提拉米蘇 | 滿 50,000 點 | 死忠 VIP(每週來約兩年) | top |

- **門檻為示意**,以客單價約 400–500 點/次反推;待高雄實際定價出來後等比例調整。
- **比例邏輯(可先定)**:入門免費 → 中階約半年常客 → 頂級約兩年死忠;0 → 1萬 → 5萬,每級約 5 倍跳,落差明顯。
- **只升不降**:累積消費永久計入,升上去不會掉(競爭壓力交給段位,會員等級當溫暖肯定)。

### 權益(讓門檻有意義)
| 等級 | 權益 |
|---|---|
| 珍珠奶茶 | 基本會員、點數錢包、入會禮 |
| 焦糖布丁 | 桌時費 95 折、生日招待飲品、配桌小優先權 |
| 提拉米蘇 | 桌時費 9 折、專屬包廂優先、商城限定品購買權、季度回饋點數 |

## 2. 段位(牌技實力)

**主題:小熊 + 材質階梯　|　依據:member_rating(類 Elo)　|　會升降**

| 階 | 顯示名 | 說明 |
|---|---|---|
| 1 | 銅牌熊 | 入門 |
| 2 | 銀牌熊 | |
| 3 | 金牌熊 | |
| 4 | 白金熊 | |
| 5 | 鑽石熊 | |
| 6 | 大師熊 | 段位頂端,達標者皆可上,可有多位 |

- 每階再分小級 **I–IV**(I 最高,如 鑽石熊 I > 鑽石熊 IV);大師熊不分小級。
- **會掉段**:輸多、放槍多會掉分降階(競技公信力來源)。
- 升降分數門檻、每階區間 → 待 member_rating 演算法定案(TBD)。

## 3. 雀神熊(頭銜,非段位)

- **全店一季僅一位**:當季大師熊中積分排名第 1 者獲得「雀神熊」稱號。
- **賽季制**:每季結算,新賽季重新爭奪;卸任者退回大師熊(實力分數保留)。
- **行銷核心**:本季雀神 = 直播/賽事/社群話題人物,餵明星 IP 線;可搭配實體獎勵(專屬包廂、獎盃、商城限定品)。
- 建議一季 = 3 個月(對齊賽季聯賽構想);長度 TBD。

## 4. 系統欄位對應

```sql
-- members 補充
alter table members add column lifetime_points bigint not null default 0;
  -- 累積消費(只增不減)→ 會員等級判定看此欄,與 wallet.balance(可用餘額,會增減)分開
-- tier 已存在:basic / mid / top

-- 升級判定:每筆消費型 wallet_txns(type in table_fee/fnb/merch/event_fee/ride)
--   accumulate 到 lifetime_points;達門檻時由 Edge Function 升 tier 並發升級通知。
--   儲值(topup)不計入 lifetime_points(避免「儲值不消費」刷等級);以實際消費為準。

-- 段位:member_rating(分數)→ 映射 rank_level(1–6)+ sub(I–IV);見資料中台文件。

-- 賽季頭銜
create table season_champions (
  season    text primary key,       -- 例 '2026Q1'
  member_id bigint references members(id),
  awarded_at timestamptz not null default now()
);
```

**關鍵設計**:升級看 `lifetime_points`(累積消費)、不是 `wallet.balance`(餘額);**儲值不算、實際消費才算**,避免大額儲值卻不來打牌就刷到高等級。

## 5. 世界級制度優化(v0.2 新增)

> 參考西洋棋 FIDE(分數浮動+頭銜終身+賽事認證)、電競(賽季+起始中間分)、精品會員(稀缺>門檻)。

### 5.1 段位:Elo 分數 + 賽事認證(norm)雙軌(防灌水)
- **分數會動、頭銜不動**(FIDE 原則):member_rating 浮動,但已認證的段位頭銜保留。
- **大師熊需「賽事認證」**:不只靠分數門檻,還須在 official 賽事(`games.is_official=true`)打出規定次數的高水準表現(MIGI 版 norm),才認證升上大師熊。
  - 目的:防止靠約打/灌水衝分;高段位才有公信力。
  - 一般段位(銅~鑽石)可純分數升降;大師熊這一階加 norm 門檻。
```sql
alter table member_rating add column norms_earned smallint not null default 0; -- official 賽事達標次數
-- 升大師熊條件:rating >= 門檻 AND norms_earned >= N(建議 N=3,對齊 FIDE 三 norm)
```

### 5.2 起始分給「中間值」,不從零爬(電競慣例)
- 新會員入場給銅牌熊區間的**中間起始分**(非 0),第一場就有輸贏刺激,利於留住新客。
- 例:rating 預設 1000(銅牌熊中段),而非從最低分起跳。

### 5.3 賽季制 + 終身榮譽牆(兩種動機通吃)
- **雀神熊=賽季制**(每季重置,保活躍與話題)——已定。
- 新增 **歷代雀神榮譽牆**:當過雀神,名字**永久**留存(App 名錄 + 實體店牆)。
  - 賽季緊張感 + 名留青史的長期誘因並存;餵明星 IP 線。
```sql
-- season_champions 已存歷季冠軍;榮譽牆 = 此表全量展示,不刪。
```

### 5.4 女子組平行頭銜(MIGI 客群定位 → 制度優勢)
- MIGI =「女生的麻將聚會店」,設**公開組 + 女子組並行頭銜**(FIDE 模式)。
- 女子組有專屬榮譽賽道,核心女性客群不必與全場最強硬拚也能奪銜;可同時持有兩種。
- 例:公開組雀神熊(全店一位)/ 女子組雀后(女子第一)。
```sql
alter table season_champions add column division text not null default 'open'; -- open / women
```

### 5.5 隱藏邀請制頂層會員(稀缺 > 門檻)
- 提拉米蘇之上,保留**不公開門檻、由店家頒發**的榮譽層:如「創始會員」「年度 MVP 客」。
- 稀缺性製造的尊榮感勝過折扣;限量/邀請制,不靠消費門檻自動觸發。
```sql
alter table members add column honors text[]; -- 例 {'founding','mvp_2026'};手動授予
```

### 設計總結
MIGI 制度 = **西洋棋的競技嚴謹(Elo+norm+終身頭銜)＋ 電競的賽季活躍(重置+起始分)＋ 精品會員的稀缺尊榮(邀請制頂層)**。
