# MIGI 成就系統企劃 v3.0｜300 枚

> **這是什麼**：成就的正式企劃，分 A~W 共 23 區。每個含名稱、客人看到的說明、
> 解鎖條件、結構軸、動機軸、**稀有度**，以及可直接上架的 schema 對映欄
> （`code`／`struct`／`motivation`／`visibility`／階段）。
> **什麼時候讀**：要實作成就系統、新增成就、或確認某個成就的判定條件時。
>
> 🔴 **取代 `成就系統企劃_200個.md`（v2.3）。** 舊版保留當對照，但**不要拿它上架** ——
> 它是 2026 年更早寫的，當時**段位、賽季、牌咖團、包桌預約、按讚、養成點心
> 六個維度全部還不存在**，而那些正是 App 這半年長出來、別家抄不走的部分。
>
> 📌 **檔名不帶枚數是刻意的** —— 枚數在定稿過程中變過很多次，
> 而檔名裡的數字是一定會漂的東西。枚數只寫在檔頭與統計段。

## 1. 對映規則（沿用 v2.3，一個字都沒改）

**結構軸 → `struct`（DB 四種）**：
特定／組合／收藏套組／對象／地點／觸發／驗證／條件事件／隱藏／稀有／限時／季節／節日／時段／日期 → `specific`；
累積分級 → `cumulative`；連續 Streak → `streak`；里程碑 → `prestige`。

**動機軸 → `motivation`（10 種）**：
完成癖→`completion`；競爭→`competition`；社交→`social`；探索→`exploration`；
收集→`collection`；榮耀/地位→`prestige`；自我表達→`expression`；劇情/話題→`story`；
消費/回饋→`consumption`。多重取主要（『/』前第一個）。

**養成規則**：凡 `struct=streak`（連續型）**一律歸 `habit`** ——
連續登入／月月報到的本質是養成回訪習慣，覆蓋原動機軸標籤。

**visibility**：含『隱藏』→ `silhouette`（灰階輪廓）；其餘 `visible`。
**收藏套組／里程碑**：trigger 為『解鎖同群 N 個』的 meta 條件，`requires_code` 留空。

**旗艦招牌成就「咪幾（MIGI）」為獨立成就，不佔這 300 的編號。**

🔴 **D 區「局勢轉折」的『正值／負值／排名』＝ 桌上積分與名次**，
非現金輸贏（守賭博紅線：MIGI 的點數只收檯費與餐飲，桌上動的是積分）。

**人稱**：全篇用「**你**」，與 App 現有文案一致。⚠ v2.3 全篇用「妳」——**兩者不可混用**。

| 稀有度 | 判準 | 枚數 |
|---|---|---|
| **普通** | 正常打牌吃飯就會拿到 | 152 |
| **稀有** | 要刻意去做，或要一點運氣 | 108 |
| **史詩** | 少數人才有：大牌型、頂級里程碑、賽季榮譽 | 40 |

🔴 **牌型（C 區）的稀有度一律照台數定，不照知名度**：
```
1–2 台   普通      4–5 台   稀有      8 台以上  史詩
```
⚠ 知名度與難度是兩回事 —— 大三元 8 台人人都知道，花槓不難但冷門。
**拿知名度當稀有度會讓「很有名但很簡單」的牌型被高估。**

## 3. 🔴 三條設計鐵則（從實際犯的錯提煉）

### 3.1 A 區用光了所有「第一次」，其他區不可以再放

A 區 29 枚是**功能導覽** —— 每個功能的第一次都在那裡。
所以其他區新增成就時，**只能是這四種形狀**：

| 形狀 | 意思 | 例子 |
|---|---|---|
| **程度** | 更大、更快、更多 | 單場破萬 |
| **組合** | 同時滿足兩個條件 | 深夜胡出大牌 |
| **稀缺** | 一天／一店只有一個 | 開店第一桌 |
| **累積** | 次數堆出來（帶 tiers） | 飲料 10／30／100 杯 |

⚠ 實際犯過的錯（初稿刪掉 10 枚重複）：
```
點心櫃開張 ＝ A16 第一個點心（逐字相同）
團員報到   ＝ A22 加入牌咖團（當時連名字都一樣；A22 於 2026-09-21 改名）
開團大吉   ＝ A21 建立牌咖團
包桌成行   ＝ A10 第一次預約包桌
台16張初體驗 ≈ A2 第一次開桌（第一場幾乎一定是台 16 張）
```

### 3.2 🔴「刷新自己的紀錄」不能當成就

曾提案「台數新高」「段位分新高」，兩個都不成立：

```
① 成就是一次性解鎖    而刷新紀錄會重複發生，解完就再也不會亮
② 第一次胡牌就是新高   0 → N 必然觸發 ⇒ 跟「首次胡牌」同時亮
③ 它本來就不是成就     「單場最高台數 16 台」是**成績頁的統計數字**
```

### 3.3 🔴 語意要精確到「不含自己」

```
舊  同桌四人都是你的牌咖      ← 你不會是自己的牌咖
新  同桌其他三人都是你的牌咖
```
⚠ 這類敘述在「同桌」「全員」「整團」的成就裡到處都是，寫的時候要逐一檢查。

### 🔴 2026-09-20 使用者拍板：**主檔裡的東西一律出現在牆上**

這一段原本寫「功能還沒做的先 `is_active = false`，
**一個永遠解不開的成就比沒有那枚更糟**」——**那句話被推翻了。**

```
拍板當天   C 區 31 枚牌型 ＋ A 區 11 枚（等電子計分／打卡／抽獎／任務／券）
          42 枚全部打開，在牆上顯示成「未達成」
```
🎯 **理由是一句話：「成就要讓人知道有什麼可以追。」**
  一個看得到卻解不開的成就是**目標**，一個看不到的成就是**不存在**。

🔴 **而真正的問題是在此之前有兩套標準，卻沒有人決定過**：
  旗艦兩枚（等 M4）看得見，牌型 31 枚（也等 M4）卻藏起來。
  日後有人問「為什麼這枚看得到那枚看不到」，答案會是「沒有人決定過」。

→ **日後匯入 S/T/U/V 那 30 枚時，`is_active` 一律填 true。**
⚠ **唯一的例外是「限時」不是「還沒做」**：V 區限定活動那種有檔期的，
  要用 **`valid_from` / `valid_to`**，不要用 `is_active` ——
  讀取端本來就在判斷效期，而**那兩個欄位會自己到期，`is_active` 要有人記得關**
  （同 CLAUDE.md 那條通則：把「記得要做 X」換成一個不需要人記得的東西）。
📌 同一天的另一半決定見下面「全系統不遮任何一枚」——
  **看得到** 與 **看得懂條件** 是同一個判斷的兩面。

⚠ **美術**：300 枚 ≠ 300 張圖。用 `achievement_tiers` 分級的成就
（累積型約 37 枚）一張圖給 3–4 次解鎖時刻 ⇒ **實際解鎖時刻約 405 次**。
現成 `badge01`–`badge10` 全部對應 A 區，**開幕只要再畫 19 張**。

## B. 牌局　27 枚　`group_key=牌局`　**階段 2**

> 🎯 這一區有兩個維度，**不要混在一起看**：
> ```
> 桌上積分  40–43  破千／三千／六千／破萬      ← session_players.final_score
> 牌型台數  44–46  深夜大牌／連場大牌／梅開二度  ← 8 台以上（＝ MIGI 的門檻）
> ```
> ⚠ **台數看的是「牌型台數」不是「總台數」** ——
> 莊家附加台（`1 ＋ 連莊數`）算進計分但**不算進成就**，
> 否則莊家連莊幾次就輕鬆達標（見旗艦那一節的算式）。
> ✅ 而它**只要那個數字、不要牌型清單** ⇒ 電子計分第一版就能上
> （客人輸入的一律是牌型台數，莊家附加台由系統自己加）。
>
> ### 🔴 40–43 的門檻會被**級距**放大，這是已知的
> 級距共 **8 級**（2026-09-20 加了 60/20 與 100/50），破千各要贏幾把：
> ```
