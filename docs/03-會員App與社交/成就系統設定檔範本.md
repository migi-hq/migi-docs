# MIGI 成就設定檔範本(總部/企劃部填寫用)v1.0

> **這是什麼**：成就設定檔的欄位範本與填寫說明。
> **什麼時候讀**：要把企劃裡的成就實際寫成設定資料時。


> 這是**總部新增成就**時填的格式,已對齊資料庫 `achievements` schema。
> 填完透過 `upsert_achievement_tx`(總部專用)寫入;分級用 `upsert_achievement_tier_tx`。
> 店長/加盟**不能**填(後端權限鎖)。

---

## 1. 欄位對照(你原本的格式 → 我們的欄位)

| 你原本寫的 | 對應到 | 說明 |
|---|---|---|
| `achievement_id` | **`code`** | 穩定代碼;DB 主鍵 `id`(uuid)由系統產生,不用填 |
| `name` | `name` | 一樣 |
| `category: "新手任務"` | (省略) | schema 用 `struct`+`flavor` 分組,沒有自由分類欄 |
| `structure_axis: "特定條件"` | **`struct`** | 值用 token:`specific` |
| `motivation_axis: ["完成癖"]` | **`motivation`** | **單值**:`completion` |
| `trigger_event` + `unlock_condition` | **`trigger`** | 合併成 `{"event":"...","count":N}`,後端自動解鎖 |
| `rarity: "common"` | **不要填** | 由系統依實際解鎖率算(`rarity_cached`) |
| `reward_type` + `reward_value: 10` | **`reward_points`** | 一次性贈點;稱號用 `grants_title`,分級獎勵用 tiers |
| `is_limited` | **`valid_from`/`valid_to`** | null=永久;填日期=限時檔期 |
| `display_order` | **`sort`** | 一樣概念 |
| `achievement_group`(牌型探索…) | **`group_key`** | 去前綴,主題族群 |
| `parent_series`(新手系列…) | **`series`** | 「parent」易誤解,改 series |
| `unlock_dependency`(是否需前置) | **`requires_code`** | 改存「前置 code」,不是布林 |
| `visibility_mode`(全顯/灰階/隱藏) | **`visibility`** | 取代 `is_hidden`;值 visible/silhouette/hidden |
| `repeatability`(一次性/每月/每季) | **`repeat_cycle`** | 值 once/monthly/quarterly |

---

## 2. 可填欄位 + 允許值

| 欄位 | 必填 | 允許值 / 說明 |
|---|---|---|
| `org_id` | ✓ | 品牌 org（全加盟共用一份） |
| `code` | ✓ | 穩定代碼,如 `beginner_001`（org 內唯一） |
| `name` | ✓ | 顯示名稱 |
| `struct` | ✓ | `specific`(特定一次) / `cumulative`(累積) / `streak`(連續) / `prestige`(榮耀) |
| `motivation` | ✓ | `completion` / `competition` / `social` / `exploration` / `collection` / `prestige`（單值） |
| `flavor` | | `mahjong` / `luck` / `wealth` / `girls` / `bear` / null |
| `visibility` | | `visible`(全顯) / `silhouette`(灰階·看得到輪廓未解) / `hidden`(隱藏,達成才現形)。**取代 is_hidden**,底層自動同步 |
| `group_key` | | 主題族群,如「牌型探索」「店內場景」 |
| `series` | | 成長系列,如「新手系列」「打卡系列」 |
| `requires_code` | | 前置成就 code(需先解鎖才會觸發);null=無前置 |
| `repeat_cycle` | | `once` / `monthly` / `quarterly`(可重複領的週期) |
| `condition_text` | | 人看的說明,如「首次到店完成一次」 |
| `trigger` | | `{"event":"<事件名>","count":N}`;有填才會自動解鎖 |
| `grants_title` | | 掛在名字旁的稱號(如 MIGI);沒有就 null |
| `is_signature` | | `true`=品牌旗艦(目前僅 MIGI) |
| `reward_points` | | 一次性贈點(`specific`/`prestige` 用;累積/連續改用 tiers) |
| `valid_from` / `valid_to` | | 限時檔期;null = 永久 |
| `sort` | | 顯示排序 |

**系統自動產生、不要填**:`id`、`rarity_cached`(稀有度=養出來的)、`is_hidden`(由 `visibility` 自動同步)、`is_active`(預設 true)、`created_at`/`updated_at`。

### 事件名(`trigger.event`)目前規劃
`visit_completed`(到店完成)、`fnb_order`(點餐一筆)、`daily_visit`(每日到店·連續用)、`migi_win`(做出咪幾)、`window_checkin`/`arch_checkin`/`table_checkin`/`drink_bar_checkin`(打卡點)、`ig_story_uploaded`(限動上傳)…(可由總部擴充)

## 3. 範例

### 範例 A — 特定·一次性(新手報到)
```json
{
  "org_id": "<brand org uuid>",
  "code": "beginner_001",
  "name": "新手報到",
  "struct": "specific",
  "motivation": "completion",
  "flavor": "bear",
  "visibility": "visible",
  "group_key": "店內場景",
  "series": "新手系列",
  "requires_code": null,
  "repeat_cycle": "once",
  "condition_text": "首次到店完成一次",
  "trigger": { "event": "visit_completed", "count": 1 },
  "reward_points": 10,
  "sort": 1
}
```
> 單一獎勵,不需 tiers。到店事件一發 → 自動解鎖。

### 範例 B — 累積 + 分級(發財糕點控)
```json
{
  "org_id": "<brand org uuid>",
  "code": "fnb_lover",
  "name": "發財糕點控",
  "struct": "cumulative",
  "motivation": "collection",
  "flavor": "wealth",
  "visibility": "visible",
  "group_key": "店內場景",
  "series": "牌局系列",
  "repeat_cycle": "once",
  "condition_text": "累積點餐達標",
  "trigger": { "event": "fnb_order", "count": 1 },
  "sort": 20
}
```
分級(另用 `upsert_achievement_tier_tx` 各填一筆):

| tier_level | tier_name | threshold | reward_points |
|---|---|---|---|
| 1 | I | 10 | 30 |
| 2 | II | 30 | 60 |
| 3 | III | 60 | 100 |
| 4 | IV | 120 | 200 |

> 每點一筆餐飲 `fire_event_tx(member,'fnb_order',1,...)` → 累積推進,跨門檻自動發該級獎勵。

### 範例 C — 旗艦·咪幾(招牌成就)
```json
{
  "org_id": "<brand org uuid>",
  "code": "migi_signature",
  "name": "MIGI · 咪幾",
  "struct": "cumulative",
  "motivation": "prestige",
  "flavor": "mahjong",
  "visibility": "visible",
  "group_key": "牌型探索",
  "series": "牌局系列",
  "repeat_cycle": "once",
  "condition_text": "做出「咪幾」(累積咪幾次數)",
  "trigger": { "event": "migi_win", "count": 1 },
  "grants_title": "MIGI",
  "is_signature": true,
  "sort": 0
}
```
分級:I ×1→100點、II ×3→200點、III ×5→300點、IV ×10→永久「MIGI」稱號+限定徽章+500點。
> 過渡期 `migi_win` 由「胡牌一鍵+攤牌拍照辨識」觸發;未來牌譜自動辨識接同一事件。

## 4. 怎麼上架(總部後端流程)

1. 填好上面的 JSON → 呼叫 `upsert_achievement_tx(p_staff_id=<hq或owner>, …欄位…)`
   - 非 `hq`/`owner` 會被擋(權限鎖)。
2. 若是累積/連續(有分級)→ 對每個 tier 呼叫 `upsert_achievement_tier_tx`。
3. 之後系統在對應動作發生時呼叫 `fire_event_tx(member, '<event>', …)` → **自動解鎖/推進**,不必為每個成就手寫邏輯。
   - 若成就有 `requires_code`(前置),`fire_event_tx` 會**先檢查前置是否解鎖**,沒解就跳過(系列成就才不會跳級)。
4. 上下架用 `set_achievement_active_tx`,移除用 `soft_delete_achievement_tx`(都限總部)。

> 部署順序:成就 schema → 總部專屬權限 → 事件自動解鎖。
