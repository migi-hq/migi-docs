# MIGI 設計 Token 規範

> 這是什麼：MIGI 會員 App（migi-web）全站設計變數的權威清單，定義於 `src/styles.css` 的 `:root`。
> 什麼時候讀它：寫任何新畫面、新元件、調整既有樣式之前。**新程式碼一律用變數，不寫死色碼與數值。**

---

## 一、色彩

### 主品牌色（雙主色）

MIGI 的品牌識別由**蜜桃粉與奶茶色並列**構成。蜜桃粉偏甜、奶茶色偏穩，搭配使用可避免畫面過於粉氣，維持溫潤而有質感的調性。

| Token | 色值 | 用途 |
|---|---|---|
| `--brand` | `#FAD6DC` | 蜜桃粉：主品牌色、按鈕、卡片 |
| `--milktea` | `#EFE3DA` | 奶茶色：主品牌色（與蜜桃粉並列）、溫潤中性、餐飲/活動/稀有 |
| `--milktea-bd` | `#DECDBC` | 奶茶深框：固定局卡外框、滿桌狀態牌文字 |
| `--milktea-light` | `#FAF5EF` | 奶茶淺底：固定局卡卡面 |
| `--milktea-ink` | `#7A5C42` | 奶茶棕字：固定局卡文字、滿桌狀態牌文字 |
| `--brand-light` | `#FFE7EE` | 淺粉：Hero 卡、提示欄底 |
| `--ink` | `#2E2B2C` | 深墨：主文字、黑底按鈕 |
| `--accent` | `#C2607A` | 桃紅：強調文字、連結、讚 icon |
| `--gold` | `#E8B89B` | 金棕：稱號邊框、點綴 |

## 二、圓角（五階）

依全站實際主力用值收斂而成，非憑空發明。

| Token | 值 | 用途 |
|---|---|---|
| `--r-pill` | `999px` | 膠囊：按鈕、chip、pill、tab |
| `--r-lg` | `16px` | 大卡：Hero 卡、抽屜 |
| `--r-card` | `14px` | 標準卡片 |
| `--r-field` | `12px` | 輸入框、小卡、黑底按鈕 |
| `--r-sm` | `8px` | 小元件：牌面、迷你按鈕 |

局部微調用的零星圓角值（3/6/10/11/13/15/18/20/22/24）刻意保留為數字，不強制收斂，避免破壞個別元件的視覺意圖。

## 六、使用方式

```jsx
// JSX inline style
<div style={{ color: 'var(--ink)', background: 'var(--milktea)', borderRadius: 'var(--r-card)' }} />
```

```css
/* CSS */
.card { color: var(--ink); border: .5px solid var(--gray-3); border-radius: var(--r-card); }
```

改任何品牌色、圓角、陰影，只需動 `:root` 一行即可全站生效。

## 七、三端統一（2026-08-15 完成）

**這份規範涵蓋三個 repo。** 三處的 `:root` 內容完全一致，可直接互相複製：

| | 定義位置 | 用法 |
|---|---|---|
| `migi-web` | `src/styles.css` 的 `:root` | `var(--brand)` |
| `migi-pos` | `src/index.css` 的 `:root` | `var(--brand)`，或 `shared.jsx` 的 `C.brand`（只是 var 的別名）|
| `migi-admin` | `src/styles.css` 的 `:root` | `var(--brand)` |

### 統一前的狀態（供理解歷史）

三個 repo 各有一套命名，**同色不同名**：

| 色值 | web | pos（舊）| admin（舊）|
|---|---|---|---|
| `#FAD6DC` | `--brand` | `C.peach` | `--peach` |
| `#C2607A` | `--accent` | `C.rose` | `--rose` |
| `#EFE3DA` | `--milktea` | `C.milk` | `--milk` |
| `#ECEAE9` | `--gray-3` | `C.line` | `--line` |
| `#F2F0EE` | `--gray-4` | `C.idle` | — |
| `#F8F7F6` | `--field-bg` | `C.card` | — |
| `#FFFFFF` | `--white` | `C.white` | `--surface` |
| `#9A9491` | `--gray-2` | `C.gray2` | `--text3` |

改品牌色要改三個 repo，而且很容易漏。

### 統一時的六項裁決

| # | 問題 | 處置 |
|---|---|---|
| 1 | `#B4AEA9` POS 與後台都在用，web 色階沒有這一階 | 新增 `--hint`（第三層弱文字）。不動既有 `--gray-*` 編號以免 web 大量改動 |
| 2 | `--danger` 兩個值：web `#B23B3B`、後台 `#C0392B` | 統一為 `#B23B3B` |
| 3 | 後台 `--text2 #6E6864` vs `--gray-1 #7A7572` | 併入 `--gray-1`（差異極小）|
| 4 | 後台 `--bg #F6F5F4` 整頁底，web 無對應 | 新增 `--page-bg` —— 整頁底與卡片底本來就該有別 |
| 5 | 後台 `--line2 #E3E0DE` | 併入 `--gray-3` |
| 6 | 陰影值不同：web `--shadow-lg` 重、後台的柔和 | 不合併。後台另立 `--shadow-card` —— 整天盯資料看，重陰影會累 |

一併刪除零使用的顏色：POS 的 `clean` / `green` / `milk` / `sakura`、後台的 `--amber` / `--green` / `--milk`。

### 語意色的用法

色票裡只有**一個警戒色**：`--danger`，而它的定義本身就寫著「錯誤／**警示**紅」——
兩種語意本來就收在同一支紅色系。所以 POS 的 toast 是：

| 語意 | 底色 | 圖示 |
|---|---|---|
| 成功 | `--brand` 蜜桃粉 | 打勾 |
| 警告 | `--danger` 警示紅 | 驚嘆號 |
| 失敗 | `--danger` 警示紅 | 叉 |

**警告與失敗同色、只差圖示**，是刻意的：不發明系統裡不存在的語意。
真的需要第三階時，先在本文件新增 token 並同步三端。

⚠ **`--accent` 不是警告色。** 它的定義是「強調文字、連結、讚 icon」，屬正向強調色。
2026-08-15 曾誤用它當 toast 的警告底色，語意是反的。

### ~~已知缺口：深金字~~ → 2026-08-15 結案，缺口不存在

POS 座位卡的稱號原本寫死 `#B8860B`（CSS 具名色 `darkgoldenrod`），
一度以為缺一個「深金字」token，還評估過候選色值。

**查了會員 App 才發現方向就錯了** —— 稱號在 `migi-web` 的個人檔案裡
（`profile.jsx:247`）根本**不是金色**，是「`「直角引號」`＋ `--ink` 深墨、無底色」。
那個 `#B8860B` 不屬於任何設計決定，是憑空冒出來的。

順帶記一筆實測：`#B8860B` 襯在稱號膠囊底（`rgba(255,255,255,.85)` 疊在 `--brand` 上，
約 `#FEF9FA`）對比只有 **3.2:1**，11px 小字的 WCAG AA 要求是 4.5:1 —— 它本來就不合格。

→ **不需要新增 token。** 稱號與段位的正式寫法見下。

### 稱號與段位（三端統一，2026-08-15）

| 元素 | 寫法 |
|---|---|
| **稱號** | `「{title}」` 直角引號 ・ `--ink` ・ **無底色** ・ 12px/700（清單列可降級）|
| **段位** | 膠囊：`rgba(255,255,255,.7)` 底 ・ `--ink` ・ 11px/700 ・ `--r-pill` ・ 高 22 ・ padding `0 11px` |

**段位一律帶「`段位: `」前綴**，由 `fmtRank()` 統一產生：

- `migi-web` — `src/lib/helpers.jsx`
- `migi-pos` — `src/shared.jsx`

兩份是同一個定義（`'段位: ' + r`）。
**同一個會員在兩端看到的字面必須一模一樣**，否則像兩套系統。

排列順序（會員 App 個人檔案為準）：**稱號 → 暱稱 → 段位**。

> `--gold #E8B89B` 維持原定義「稱號**邊框、點綴**」，與稱號文字無關，兩者不衝突。

> **選人清單刻意不顯示稱號** —— 選人時要找的是「誰」，
> 稱號是成就展示，放進挑人清單只是每列多一行雜訊。

### 規矩

**要用顏色一律 `var(--xxx)`，不要寫死色碼，也不要自己調色。**
本表沒有的色階，先在這裡新增 token 並同步三端，不要在單一 repo 塞字面值 ——
2026-08-15 就發生過：POS 的 toast 需要警告色，我直接編了一個 `#F3C969` 琥珀，
而三端既有的語意色其實是 `--accent` 與 `--danger`（後者註解就寫著「錯誤／**警示**紅」）。
