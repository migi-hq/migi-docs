# MIGI 顏色對比規範（WCAG AA）

> **這是什麼**：哪一個 token 可以拿來當文字、站在哪一種底上、保證多少對比。
> **什麼時候讀它**：挑文字顏色之前，以及新增任何色票之前。
>
> 🔴 **這份文件不列色值。** 值的唯一來源是 `migi-assets/tokens.json`
> （硬規則 13）。這裡只寫**值放不下的東西：規則與保證**。
> ⚠ 抄一份值進來就是這個專案記過六次的病 ——
> 而 `設計Token規範.md` 2026-09-09 之前正是那樣，於是它的灰階值漂了兩版沒人發現。

---

## 一、立場：內建，不是檢查

世界級的設計系統都參考 WCAG，但**差別在它出現在流程的哪一段**：

| | 做法 | 代價 |
|---|---|---|
| 一般 | 做完了跑工具掃一遍再修 | 一次 95 個修改點，散在五個頁面 |
| **世界級** | **寫進色票**：挑顏色那一刻就決定了 | 一次，之後每個畫面自動符合 |

```
Shopify Polaris   每個文字 token 標註它保證的對比級別
IBM Carbon        色票文件直接列對比值，另有 $link-primary 這種「文字專用」色
Google Material   tonal palette，深淺是算出來的不是挑的
Atlassian         token 分 text / background / border 三族
```

🎯 **重點不是「他們比較有良心」，是那樣比較便宜。**

⚠ **MIGI 沒有法規義務**（台灣的無障礙規範強制的是政府網站）。
這份文件的理由是實務的：

| | 為什麼在意 |
|---|---|
| 官網 `migi.tw` | 陌生人唯一會看到的那一個，也是送廣告審核時被看的 |
| 會員 App | **客群年紀偏大** ＋ 手機常在戶外看，實際對比比你在電腦前更差 |
| POS | **唯一一個有人盯著看八小時的**，而且在麻將館的燈光下 |
| 總部後台 | 使用者是自己人，最不急 |

## 二、AA 的實際規則（只有三條）

對比值 = 前景與背景的相對亮度比，範圍 `1:1`（同色）到 `21:1`（純黑配純白）。

| 情況 | 門檻 |
|---|---|
| 一般文字 | **4.5:1** |
| 大字（≥24px，或 **≥18.7px 且 ≥700 粗**） | 3.0:1 |
| 非文字（icon、邊框、圖表） | 3.0:1 |

🔴 **MIGI 的小字是 11–13px，全部算「一般文字」** ⇒ 一律看 4.5。

⚠ **對比是對稱的**：`A 字在 B 底` 與 `B 字在 A 底` **是同一個數字**。
📌 2026-09-09 我一度說成「文字要深才在白底過、底要深白字才過，兩個方向互相拉扯」——
**那是錯的**，沒有拉扯。

## 三、角色 → token 對照（這一節才是規範本身）

**實測值，不是估的**（2026-09-09 用執行期掃描量的，方法見第五節）。

### 文字色

| token | 角色 | 白底 | `--brand-tint` | `--brand` |
|---|---|---|---|---|
| `--ink` | 主文字 | ✅ 14+ | ✅ | ✅ |
| `--gray-1` | **要讀的次要文字** | ✅ 7.13 | ✅ 6.29 | ✅ 5.33 |
| `--gray-2` | 標籤、時間戳 —— **讀得到就好** | 🟡 3.79 | 🟡 3.34 | 🔴 2.84 |
| `--hint` | **刻意退到背景**（佔位提示） | 🔴 2.19 | 🔴 1.94 | 🔴 1.64 |
| `--accent` | 🔴 **不要拿來當文字**，見下 | 🟡 4.00 | 🟡 3.53 | 🔴 2.99 |

### 🔴 規則一：要被讀的文字用 `--gray-1`，不要用 `--gray-2`

`--gray-2` 在**任何**底上都不到 4.5。它的角色是「有就好」的標籤，
**不是「客人需要讀懂的句子」**。

⚠ 特別是**站在 `--brand` 粉底上時只有 2.84** —— 連大字的 3.0 都不到。
段位 Hero 的底就是 `--brand`。

### 🔴 規則二：`--accent` 是填色，不是文字色

```
--accent      填色：進度條、膠囊底、按鈕底、icon
--accent-text 文字：查看 ›、+30、強調數字        ⏳ 待拍板（見第六節）
```

🎯 這是硬規則 13.7 的同一個判準（`--divider` 從 `--gray-4` 拆出來時用的）：
**「這個值改了，哪些東西會跟著動？」超過一種用途就該拆。**

⚠ **不要用「把 `--accent` 改深」解決** —— 那會讓進度條與膠囊底一起變深，
而那不是要解決的問題。品牌色是為了「好看」挑的，不是為了 4.5 挑的。

### 🔴 規則三：深色底一律配 `--white`

`--gray-1` 站在 `--ink` 上只有 **1.97**（加深之前是 3.08 —— 也不合格）。
✅ 2026-09-09 掃過三端，**「深底 ＋ 灰字」是 0 處**，這條目前沒有被違反。

### 背景色（不當文字用）

`--gray-3` / `--gray-4` / `--field-bg` / `--page-bg` / `--divider` /
`--brand-tint` / `--brand-light` —— **這些只當底或線，不要拿來寫字。**

## 四、刻意不修的三類（理由各不相同）

**不修 ≠ 沒看到。** 每一類的理由不一樣，混在一起會讓下一個人以為是漏掉的。

### ① `--gray-2` 白底 3.79（約 45 處）—— 修了會塌掉階梯

要過 4.5 得拉到約 `#7B7673`，而那跟 `--gray-1` 幾乎一樣
⇒ **剛做好的等距灰階就沒有中間階了**。

📌 白底上 4.5 的分界線大約在 `#7B7673`，也就是說：
**這條灰階不可能既等距、又每一階都過 AA。**
要三階全過，它們得全部擠在 `#7B7673` 到 `--ink` 之間，會長得幾乎一樣。
⇒ 現況是一個**有意識的分工**，不是妥協。

### ② LINE 綠底白字 2.26（1 處）—— 不能改

LINE 官方明文規定登入按鈕的顏色與形狀**不可修改**
（`--line-green` 的 token 描述也寫了「不是我們的設計決定」）。

### ③ `--hint` 全部不合格 —— 那是它的工作

它存在的目的就是「退到背景」（輸入框的佔位提示）。
⚠ **但不要拿它寫任何客人需要讀的東西。**

## 五、怎麼自己量

🔴 **要用執行期掃描，不要靜態掃描** —— 背景色常常來自祖先元素，
而 inline style 看不出來。`getComputedStyle` 才是準的。

掃描器有三件事非做不可，少一件結果就是錯的：

```
① 半透明背景要逐層混合    rgba 直接算會得到錯的比值
② 門檻依字級而定          大字 3.0、一般 4.5
③ 只看「自己有文字節點」的元素   否則父層會被重複計算
```

📌 完整實作見 `docs/_資產/`（2026-09-09 那次掃描）。
執行方式：起 dev server → **先裝寫入攔截器**（硬規則 11.6）→ 走過五個分頁 → 收集。

⚠ **掃描前要種一個 `is_test` 的身分** —— 本機 dev 連的是正式資料庫。

## 六、決策紀錄

### 2026-09-09：灰階加深並拉回等距（`@migi/assets` v1.6.0 → v1.7.0）

起因是使用者說「本季段位分」那類小字讀不清楚。

```
hint → gray-2 → gray-1 → ink        每階約 −44（實測）
```

🎯 **而它修好了一件沒有人知道壞掉的事**：加深之前 `--gray-1` 站在
`--brand-tint` / `--gray-4` / `--brand-light` 上是 **3.88–4.01**，
**未達 AA**。使用者是憑「讀不清楚」講的，而那個直覺對上了一個可以量的標準。

⚠ `--gray-2` 的值是**算出來的不是挑的**（取 `hint` 與 `gray-1` 的逐通道中點）。
🔴 **這四階要動就一起動** —— 只改其中一個就會出現「中間那一階卡住」。

### ✅ 2026-09-09：`--accent-text` 拆出來（v1.8.0）

候選值（實測），選 `#974B5F` —— **唯一在五種底上都過的**：

| | 白 | tint | brand |
|---|---|---|---|
| `--accent` `#C2607A` | 4.00🟡 | 3.53🟡 | 2.99🔴 |
| `#B45971` | 4.56✅ | 4.02🟡 | 3.41🟡 |
| `#A64C63` | 5.48✅ | 4.83✅ | 4.10🟡 |
| **`--accent-text` `#974B5F`** | **6.02✅** | **5.31✅** | **4.51✅** |

🎯 最難的 `--brand` 那一格**不是特例**：段位 Hero 的「再 40 分」就站在那裡，
那是成績頁第一眼最該讀得到的東西。

**成果：95 筆／20 組合 → 59 筆／8 組合**，`--accent` 當文字的失敗全部消失。

📌 預覽：`docs/_資產/accent-text候選值.html`

### 🔴 整批替換踩到的兩個坑（都是「過濾條件寫錯」）

替換 90 處時做錯兩次，**兩次都不是想法錯，是過濾器錯**：

```
① 條件用「這一行含 color」
   ⇒ 同時有 background:accent 與 color:white 的膠囊，背景也被換掉（27 → 16）
② 檢查誤改時用 grep -vi "color:" 排除
   ⇒ 而 borderTopColor: 裡面就含 Color: ⇒ 邊框那幾行被過濾掉沒顯示
   ⇒ 我因此宣告「乾淨」，而它不乾淨
```

✅ **兩次都是靠「總數要對得上」抓到的**（`78 + 79 = 157`）——
單看「有沒有出現不該出現的東西」兩次都會過。
🎯 **凡是整批替換，先記下基準總數，改完要能加回同一個數字。**

正解：**大小寫敏感 ＋ 要求 `color` 在前**的正則 ——
`backgroundColor` / `borderTopColor` 是大寫 C，**天然分得開**，
不需要另外排除（而「另外排除」正是第 ② 個坑的來源）。

### ✅ 順手修掉一個不走 token 的硬寫色

```
#7A6F6C   獎勵頁小熊心情那一行 → 換回 var(--gray-1)
```
📌 它的值幾乎就是**舊的** `--gray-1`（`#7A7572`）——
也就是有人手調了一份出來，然後 token 加深時它沒有跟著動。
**那正是「第二份定義」最典型的樣子：不會報錯，只會慢慢跟本尊分家。**

⏳ 還有一個沒動：`#FAF5EF`（配桌的某個底）——
它與 `--milktea-light` 同值，可能是漏了沒換，但它是**底色不是文字**，
不影響對比，留給下次順手處理。

### ⏳ 剩下唯一可決定的一項：白字站在 `--accent` 上（12 處）

```
#FFFFFF on #C2607A  =  4.00     通知紅點的數字、「每天開桌」那類膠囊
```
兩條路：
· 那些膠囊的**底**改用 `--accent-text`（白字 on `#974B5F` = 6.02 ✅）
· 或膠囊的**字**改用 `--ink`

⚠ 前者要面對一個命名問題：`--accent-text` 當**背景**用讀起來很怪。
真的要走那條，token 名字應該是 `--accent-deep` 之類（那是 v1.9.0 的事）。

## 七、新增色票之前要回答的三個問題

1. **它是文字還是填色？** 兩者都要就該拆兩個 token（規則二）。
2. **它會站在哪些底上？** 全部量一次，**最難的那一個決定值**。
3. **既有的色票裡真的沒有嗎？** 硬規則 13.5 的同一條 ——
   挑不到就提出來討論，不要因為「差一點」就加一階。
