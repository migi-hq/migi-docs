# MIGI 店員後台（POS）規劃 v1.2

> **這是什麼**：店員 POS 的功能規劃與優先序。
> **什麼時候讀**：開始做 POS 介面時。付款方式與紅線已更新為新金流鐵則。


> **v1.2（2026-07-13）**：付款模式更新為「元計價 + 混合付款」。舊「桌面不見現金／一律走點數／現金不足先儲值」已作廢，改新金流鐵則。權威文件：《MIGI_開桌結帳流程規格_v2.0》。

> **定位**：麻將館版的 POS —「桌台管理 + 配桌撮合 + 結帳」的混合體。
> **網址**：staff.migi.tw（獨立前端，非 LIFF，平板/電腦用，Supabase Auth 店員登入）
> **對象**：門市現場店員。RLS 綁 store_id（只看得到自己店）。
> **前置**：需 M2 後端 RPC（開桌/收桌/配桌/撮合）先到位。

---

## 0. 店員的一天（情境）— POS 要支援的動線

```
開店 → 客人陸續來 → 報到（會員/散客）→ 配桌或包桌 → 開桌（收檯費·點數/現金/混合）
  → 打牌中（桌台看板監看、點餐、中途加人）→ 收桌結算
  → 客人離店 → 翻桌整理 → 下一輪
中間穿插：券核銷、儲值、人工撮合落單的客人、處理客訴
```

POS 要讓店員**一眼看到全店桌況**，並快速完成「開桌 / 撮合 / 收桌」三個高頻動作。

## 2. 各頁面功能細節

### P1. 桌台看板（主頁 · 最重要）
店員開店後一直停在這頁。全店桌台狀態一目了然。

**顯示**：
- 每張桌一個卡片，狀態用顏色分：
  - 🟢 空閒（idle）→ 點了可「開桌」
  - 🔵 使用中（occupied）→ 顯示坐了誰、幾將、開桌多久 → 點了可「收桌 / 中途加人 / 點餐」
  - 🟡 整理中（cleaning）→ 點了可「設為空閒」
  - ⚫ 停用（disabled）
- 頂部摘要：目前開桌數 / 空桌數 / 等待配桌人數（紅點提醒去 P4 撮合）

**操作**：
- 點空桌 → 進 P2 開桌
- 點使用中的桌 → 桌次詳情（收桌 / 加人 / 點餐 / 作廢）
- 頂部「等待中 3 人」→ 進 P4 撮合看板

**接**：list_tables_tx（桌況）、Realtime 訂閱桌況變化

---

### P2. 開桌
兩種來源：系統配桌自動開 / 店員手動開。這頁是**店員手動開桌**。

**流程**：
1. 選這桌要坐的客人（掃碼 / 手機搜尋 / 從等待名單挑）
2. 選積分級距（stake_level）
3. 選規則（台麻無花/有花/美麻）
4. 確認 → 開桌
   - 每人收檯費（配桌 150 元 / 或包桌時間階梯 400/600/800 元）
   - **★付款方式三選一/混合：純點數 / 純現金 / 點數+現金混合**
   - 桌狀態 → occupied
   - ~~現金不足 → 提示先儲值（cash→points）~~ **【v1.2 作廢】** → 點數不足直接用現金補即可；儲值改為客人自願（用優惠誘因，不強迫）

**注意**（v1.2 新紅線，取代舊「桌面不見現金」）：
- ~~桌面不見現金，一律走點數~~ **【作廢】**
- **①一律會員無例外**：純現金客人也要建會員（店員可代開：手機+姓名，line_user_id 留空）。沒有會員 = 消費/關係/業績/段位都掛不上
- **②一律入帳，現金也不例外**：每筆收款都要在 POS 記 order_payments（method=cash/credit_card/line_pay + 實收/找零），沒有私下收現金的路徑
- **③賭資不上桌**：MIGI 只收場地費與商品費，不經手牌桌輸贏
- 包桌 vs 配桌計費不同（配桌 per-head、包桌計時階梯）
- **★現金結帳要有收銀確認流程（實收/找零）**——這是 v1.2 新增的 POS 需求

**接**：`open_session_tx`（**⚠️ 待開發：此函式尚未建立，非修改既有**）/ `charge_matched_tx`（✅ 已存在）/ `charge_private_tx`（✅ 已存在）/ `checkout_tx`（✅ 已存在，tender 模型可直接用於混合付款）

---

### P3. 收桌結算（★M2 簡化：只收檯費，不算名次/段位）
打完牌，店員收桌。**M2 階段刻意簡化**：不輸入名次、不算段位（名次等 M4 牌譜 AI 辨識再補）。

**流程（M2 版）**：
1. 選要收的桌
2. 確認收桌（**不用輸入名次**）→ settle_session_tx（M2 模式）觸發：
   - ✅ 收檯費（結算費用）
   - ✅ 消費累積（會員 tier）
   - ✅ 店員業績（配桌獎金/綁定客人）
   - ✅ ★跳「要不要互加牌咖」（推到客人 App）
   - ❌ **段位計算 → M2 先關閉**（等 M4 有名次自動觸發）
3. 桌狀態 → cleaning（待整理）

**★名次/段位的未來（M4）**：
- M2 收桌不碰名次，段位系統掛著不動
- M4 牌譜 AI 辨識好後 → 收桌帶入名次 → settle 才開始算段位（+30/+10/−10/−30）
- 過渡期不用店員手 key 名次（不可靠）

**接**：settle_session_tx（已寫好，M2 用「只收費」模式，段位參數留空/關閉）

---

### P4. 人工撮合看板（★護城河最深）
店員看到零散等待的客人，主動兜成一桌。

**顯示**：
- 等待中的客人清單，按門市/積分分組：
  - 「50/20：小明、小華」
  - 「30/10：阿強」
  - 「100/20：美美」
- 每人顯示：暱稱、想打積分、等待時長、性別（配桌參考）

**操作**：
- 勾選 2~4 人 → 「兜成一桌」
- 系統檢查黑名單（互黑的人擋下、提示）
- 確認 → staff_match_tx 開桌（標記 is_staff_matched，發配桌獎金）

**價值**：這是店員創造成桌率的地方，也是配桌獎金來源。UI 要快、一眼看出誰能湊。

**接**：list_match_queue_tx（等待名單）、staff_match_tx（撮合）

---

### P5. 客人報到 / 查詢
**流程**：
- 掃客人 QR（LIFF 會員碼）或輸入手機號 → 帶出會員
- 顯示：暱稱、段位、點數餘額、可用券、消費 tier
- 可操作：儲值（wallet_topup_tx）、查交易紀錄
- 散客（非會員）→ 引導註冊，或店員代開臨時身分

**接**：查會員 RPC、wallet_topup_tx

---

### P6. 券核銷
記憶：LAUNCH 階段核銷只做「③店員選客人套用」。

**流程**：
- 選客人 → 看他的可用券 → 選一張 → 套用（redeem_coupon）
- 例：暢打券 → 開桌免檯費

**接**：redeem_coupon（已寫好，23 pass）

### P7. 桌邊點餐處理

**流程**：
- 訂單看板：新訂單 → 製作中 → 已出餐
- 店員更新訂單狀態
- 點數結 or 現金結（已有雙通道邏輯）

**接**：set_order_status_tx（已寫好）

### P8. 當日報表
記憶：最小報表後端已完成（daily_report_tx）。

**顯示**：營收 / 毛利 / 來客 / 客單價 / 開桌數 / 桌台使用率

## 3. 技術架構

| 項目 | 選擇 |
|---|---|
| 前端 | React（獨立 repo / staff.migi.tw）|
| 登入 | Supabase Auth（email/password），非 LINE |
| 權限 | RLS 綁 store_id，店員只看自己店 |
| 即時 | Supabase Realtime（桌況/等待名單即時更新）|
| 裝置 | 平板橫式為主（櫃台），也支援電腦 |
| 設計 | 跟隨 MIGI CIS（白底+粉點綴），但**資訊密度高**（POS 要快速操作，不是會員端的精緻感）|

> **店員端 vs 會員端設計差異**：會員端重「精緻、溫暖、品牌感」；店員端重「快、清楚、資訊密度、誤操作防呆」。同 CIS 色但排版更工具化。
