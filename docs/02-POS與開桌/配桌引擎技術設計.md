# MIGI 咪吉麻將 — 配桌引擎技術設計 v0.2

> 範圍:配桌(媒合)引擎與其直接依賴的資料表。
> 技術棧:PostgreSQL / Supabase。
> 牌譜事件庫、成績聚合與 OLAP(資料中台主體)為另一份文件,本文僅定義兩者的接縫 `member_rating`。

---

## 1. 設計概念

配桌引擎 = **約束求解器(constraint solver)+ 評分器(scorer)**。

- **硬約束**:不通過就不可能同桌(黑名單、時間窗、空桌、點數)。
- **軟評分**:在所有「通過硬約束」的組合中,挑分數最高的一組。

媒合流程:`分桶 → 列出候選組合 → 過硬約束 → 算軟分 → 取最高分 → 配桌通知`。湊不齊則進候補佇列;有人離桌則觸發替補。

## 3. 配桌演算法(虛擬碼)

```text
function runMatchmaking(store_id):
  for each (game_type, stakes_level) bucket at this store:
    pool        = match_requests where status='waiting' and same bucket,
                  order by priority_score desc, requested_at asc
    free_tables = tables where status='empty' and game_type matches
    if free_tables is empty or pool size < seatsNeeded(game_type): continue

    seats = seatsNeeded(game_type)          # 4 或 3
    best  = null
    for combo in candidateCombos(pool, seats):   # 由高優先請求往下剪枝
        if not passesHard(combo): continue
        s = softScore(combo)
        if best is null or s > best.score:
            best = { combo, score: s }
    if best is not null:
        table = free_tables.pop()
        seatGroup(best.combo, table)        # 見 seatGroup()


function passesHard(combo):
  # 1) 黑名單:任兩人之間不得有 block/avoid 邊(雙向)
  for (a, b) in pairs(combo):
      if existsRelation(a, b, in ['block','avoid']) or
         existsRelation(b, a, in ['block','avoid']):
          return false
  # 2) 時間窗:全員可玩時間交集 >= 預估時長
  est = estDuration(combo, store_id, game_type)
  for m in combo:
      if m.available_until is not null and
         (m.available_until - now) < est:
          return false
  # 3) 點數足夠(場地費)
  for m in combo:
      if walletBalance(m) < tableFee(store_id): return false
  return true


function softScore(combo):
  score  = 0
  score -= W1 * stddev(ratingOf(m) for m in combo)      # 段位越接近越好
  score += W2 * countSatisfiedPrefer(combo)             # 固定咖/好友湊在一起
  score += W3 * maxWaitMinutes(combo)                   # 等越久越優先
  score += W4 * windowUrgency(combo)                    # 時間窗快關的先排
  score += W5 * lapsedReturnBonus(combo)                # 回流會員加權
  return score


function seatGroup(combo, table):
  for each request r in combo:
      r.status            = 'matched'
      r.matched_table_id  = table.id
      r.matched_at        = now()
      r.confirm_deadline  = now() + CONFIRM_WINDOW    # 例:5 分鐘
  table.status = 'reserved'
  LINE_push(combo, "您的桌湊齊了,請於 5 分鐘內確認入座")
```

`estDuration` 取自 `duration_model`,可隨牌譜歷史持續回算,讓預估越來越準。
`commitment='flex'` 視為較寬鬆;指定 `Nhanchan` 則以 `N × minutes_per_hanchan` 估算。

## 4. 候補佇列與替補(解時間問題)

候補佇列 = `match_requests where status='waiting'`,以 `priority_score` 排序。

替補:當進行中的牌局有人離桌(到點 / 中離),用剩下三人當約束,從候補挑最佳補位者,牌局延續——把「桌的壽命」與「個人要打多久」解耦。

```text
function onSeatVacated(game, seat):
  remaining = members still seated in game            # 通常 3 人
  bucket    = (game.game_type, game.stakes_level, game.store_id)
  cands     = match_requests where status='waiting' and same bucket
  best = argmax over c in cands
              where passesHard(remaining + c)
              of    softScore(remaining + c)
  if best exists:
      assignSeat(game, seat, best)                    # status='seated'
      LINE_push(best, "有一個位子空出,N 分鐘內確認")
  else:
      mark seat open; offer 併桌 / 暫休 to remaining
```

## 5. 優雅降級(湊不齊時)

務必逐步放寬,且**永遠不揭露**是因為「誰在場」:

1. 先丟掉軟性偏好(仍保留所有硬約束)。
2. 放寬段位區間容忍度。
3. 放寬「軟性」時間容忍(`hard_stop=true` 絕不放寬)。
4. 仍湊不出 → 留在候補,並可提示會員「目前無合適桌,要不要放寬條件或稍候」。

為避免媒合死結:**每位會員的 personal `avoid` 邊設上限**(例如最多 N 人)。

---

## 6. 確認與 no-show

- 配桌後保留座位至 `confirm_deadline`。
- 逾時未確認 → `status='no_show'`,扣 `priority_score`(降低未來優先權),並對該桌重跑媒合。
- 重複 no-show 者持續累扣,防止佔位不來。

## 7. 隱私與權限(Supabase RLS 重點)

- `relations`(personal scope):**只有 from_member 自己**可讀寫;被迴避的一方查詢不到任何相關列。媒合在後端(service role)雙向檢查,結果不外顯。
- `relations`(store scope):僅店員/管理者可建立與查看 `note`。
- `match_requests` / `member_rating`:會員僅能讀自己的列;媒合運算以後端排程(Edge Function + service role)執行。
- 行為資料(段位、戰績)屬個資,對外分析請於另一層假名化處理(詳見資料中台文件)。

## 8. 效能與部署註記

- 熱路徑索引已建於 `match_requests (store_id, status, game_type, stakes_level, priority_score desc)` 與 `relations (from_member)/(to_member)`。
- `candidateCombos` 必須剪枝:先取桶內優先度最高的前 K 筆再組合,避免 C(n,4) 爆炸。
- 媒合排程:建議以 Supabase Edge Function 定時(或事件觸發)執行 `runMatchmaking`,而非前端呼叫。
- 部署順序:先建型別(enum)與資料表 → 後端媒合函式 → 前端(LIFF)送出請求介面。所有 SQL / Edge Function 部署一律走 Supabase Dashboard。

## 10. 換手與「將制」策略(v0.2 新增)

### 10.1 將制鐵律(營運規則 → 系統規則)
- 一桌的承諾單位是「將」;**一場(session)預設 3 將**。
- 換手**只發生在將與將的邊界**,絕不接手打到一半的牌。
- **接手者打的是「剩餘將數」,不重開 3 將**(實務鐵律:接手後通常打剩下的 2 將)。
- 每將獨立結算成績;補位者的戰績**從他加入的那一將起算**,之前的將與他無關。
- 費用照舊:依「實際在座時段」計費,與將數脫鉤。

### 10.2 Schema 調整

### 10.3 補位媒合:剩餘將數是一級條件
```text
function onSeatVacated(game, seat):           # 於將邊界觸發
  remaining_sets = game.planned_sets - game.current_set + 1   # 含即將開始的這一將
  est = remaining_sets * minutes_per_set(store, game_type)
  cands = waiting requests in same bucket
  best = argmax over c in cands where
           passesHard(remaining_players + c)
           and timeWindow(c) >= est                 # 硬約束:夠打完剩餘將
         of softScore(...) + W6 * commitMatch(c, remaining_sets)
  # commitMatch:候補者想打的將數與剩餘將數越接近,加分越高
  # → 想打 2 將的人接「剩 2 將」是完美匹配,不是將就
  notify(best, "T_x 桌剩 {remaining_sets} 將、預計 {est} 分鐘")   # 通知必須透明標示
```

### 10.4 心理面配套(把「撿剩的」翻成「賺到的」)
1. **救場獎勵**:補位成功 → 場地費折扣 / 招待飲品 / 下次配桌優先權 +1,寫進補位通知卡。
2. **派發順序**:該桌成員的 prefer(固定咖)→ 離場者好友 → 一般候補。熟人圈接位 = 朋友揪,不是接陌生局。
3. **員工代打制度**:候補無人接時由受訓店員撐桌,`is_staff_seat=true`、該席成績不計排名;店員選手同時是明星養成人才池。
4. **桌權選擇**:有人離場時,桌上其餘玩家可選「找人接位 / 改打三人 / 收桌」,不強塞。

### 10.5 成績歸屬
- `member_stats_agg` 聚合時以 `hands.set_no` 對照 `game_seats.joined_set / left_set`,只計入「該玩家在座的將」。
- `is_staff_seat=true` 的席位一律不寫入 `member_rating`(或寫入獨立的 staff 表)。

### 10.6 將中離桌處理(v0.2.1 新增:連將邊界都來不及的突發狀況)

**分層協定:**

| 層 | 情境 | 處理 | 計分 |
|---|---|---|---|
| 1 | **暫離**(電話/廁所/臨時處理) | 店員「**暫代**」代打數局,本人回座換回 | 照算原玩家(觸發暫代打法) |
| 2 | **中離** + 有店員 | 店員「**接手**」接手打完此將 → 將邊界後接正常換手流程(§10.3) | 中離者已完成的局照算;店員接手後的局不計排名;此將名次對中離者記棄局 |
| 3 | **中離** + 無店員可頂 | 桌權三選:(a) 中止此將(已完成局有效,提前進入將邊界→補位/三人/收桌)(b) 改三人續完 | **已完成的局永遠有效**,僅進行中那一局作廢 |
| 4 | 制度面 | 中離記點扣 priority_score(同 no-show 機制);累犯只配入短場/休閒桶;**身體不適/急事由店長一鍵豁免不記點**;被中離的三家自動發致歉補償(飲品/小額點數) | — |

**Schema 補充:**
```sql
-- 座位狀態事件(暫離/暫代/中離)
create type seat_event as enum ('away','proxy_start與proxy_end','quit_midset','resume');
create table seat_events (

  game_id   bigint   not null references games(id),

  member_id bigint,

  set_no    smallint not null,

-- 中離記點:沿用 match_requests.priority_score 扣分機制;

**預防設計:** LIFF 提供「緊急離場」按鈕 → 同步通知店員到桌 + 觸發暫代/接手判斷流程,給突發狀況正式出口。

**營運前提:** 每班次至少一名會打牌的受訓店員,暫代/接手是必備營運能力,同時兼任明星養成人才池(§10.4-3)。

## 11. 規則集為媒合條件(v0.2.2)
- **鐵律:北部台有花、南部台無花。** `ruleset`(tw16_noflower / tw16_flower)是配桌硬約束之一:有花桌與無花桌不可混。
- `match_requests` 增加 `ruleset`;passesHard 須檢查同一桌 ruleset 一致。
- 單店通常只開一種(高雄=無花);跨店/加盟時此欄確保玩家配到正確規則的桌。
