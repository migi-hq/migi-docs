# MIGI 麻將連鎖 — 開桌結帳流程規格 v2.0

> 每天營運最高頻的核心流程。
> **v2.0（2026-07-13）重大更新**：付款模式由「全程點數」改為「元計價 + 混合付款」。
> v1.0 的「所有付款先轉點數，無一例外」**已作廢**，改為新鐵則（見 §5）。
> 設計原則：**元計價 · 付款彈性（點數／現金／混合）· 一律會員 · 開桌即收 · 網咖式超時提醒（不偷扣）**。
> 開桌方式：櫃台報到 + 雙軌開桌（滿四自動／店員手動），身分雙軌（報手機／掃 LIFF 會員碼）。

---

## 0. v1.0 → v2.0 改了什麼（一眼看懂）

| | v1.0（舊，已作廢） | v2.0（現行） |
|---|---|---|
| 計價單位 | 點 | **元（新台幣）** |
| 付款方式 | 一律先轉點數，無例外 | **純點數／純現金／點數+現金混合** |
| 檯費性質 | 「桌面不見現金」故必須走點數 | **檯費＝場地使用費，可直接收現金** |
| 點數角色 | 唯一計價與消費單位 | **付款方式（tender）之一**，1 點 = 1 元 |
| 會員 | 因為要儲值，所以必為會員 | **仍必為會員**（理由改變，見 §5） |
| 收費時機 | 開桌即扣 | **開桌即收**（不變） |

**紅線沒有放寬，只是守法改變**：牌桌上不見的是**賭資現金**（輸贏籌碼）；場地使用費是正常服務收費，收現金天經地義。

## 1. 兩套計費規則（單位：元）

### 配桌（系統湊桌 · 按人頭）
| 情況 | 收費 |
|---|---|
| 打滿 3 將 | 150 元/人 |
| 中途加入未滿 3 將 | 100 元/人 |
| 遲到、棄賽未滿 3 將 | 照收 150 元/人 |

**邏輯**：佔了系統配好的位子就要付。只有「中途加入」（非自願、半路進場、本就不可能打滿 3 將）給低消 100；遲到、棄賽是自己責任，照收 150。守住「佔位就付、保護成桌率」。

### 包桌（自己一桌 · 按時間階梯 · 整桌計）
| 時段 | 收費 |
|---|---|
| 0–2 小時 | 400 元/桌 |
| 2–5 小時 | 600 元/桌 |
| 5–24 小時 | 800 元/桌（封頂） |

**邏輯**：不跟陌生人併桌、不限將數、有隱私。封頂 800 對「自帶整團久坐」友善，呼應招團策略。
**實作**：級距存 `pricing_tiers`（mode='private'，min_unit/max_unit = 分鐘），可後台改價、可分店覆寫。

---

## 2. 收款邏輯（開桌即收）

**原則：開桌前先確認條件（配桌/包桌、幾人、預估時段），開桌瞬間就收，不等收桌。**

### 配桌
| 對象 | 收款時機 | 金額 |
|---|---|---|
| 開桌時在場的人 | 開桌瞬間 | 收 150（以打滿 3 將基準） |
| └ 打滿 / 遲到 / 棄賽 | 收桌 | 不退（維持 150） |
| 中途加入的人 | 加入當下 | 收 100（獨立事件，不是「先收150再退50」） |

### 包桌
- 開桌前問「打多久」→ 直接收對應階梯整桌價
- 超時 → 見 §3

### ★付款方式（每一筆收款都適用）
客人可選：
- **純點數**（錢包餘額折抵）
- **純現金**
- **點數 + 現金混合**（點數折一部分，餘額現金補足）

系統邏輯（checkout_tx 既有 tender 模型，天生支援）：
```
應付金額（元）
  → 券折抵
  → 會員等級折扣
  → 點數折抵（客人決定用多少，上限 = min(餘額, 應付)）
  → 剩餘 = 現金／刷卡／LINE Pay 收足
```

---

## 3. 超時提醒（網咖式）

- 時段快到**前 10 分鐘**，系統跳提醒（店員端 + 推播客人）
- 客人決定：
  - **要續** → 補收升階（2hr→5hr 補 200；5hr→24hr 補 200）
  - **不續** → 在時限內準備收桌
- **不自動偷扣** → 客人有掌控感，呼應「安心」品牌定位

---

## 4. 完整生命週期

```
① 報到（LINE 掃碼／報手機 → 認出會員、餘額、偏好、預約）
      ↓ 選模式
   ┌──────────────┬──────────────┐
   配桌                          包桌
   湊滿4人→指定桌→開桌            先問打多久→開桌
   開桌收 150/人（在場）          開桌收階梯價（400/600/800）
   中途加入→收 100               超時前10分提醒→續（補200）/不續
   ★付款：點數／現金／混合         ★付款：點數／現金／混合
   收桌：遲到棄賽不退              收桌：依最終階梯
   └──────────────┴──────────────┘
                  ↓
   收桌完成 → 三項自動更新：
     · 消費累積（會員分級：珍奶→焦糖布丁→提拉米蘇→主廚特調）
     · 牌局成績（段位 Elo）
     · 店員業績歸因（成桌獎金）
```

> 註：v1.0 有「點數不足 → 先儲值再扣」這一關，v2.0 已移除——點數不足直接用現金補即可，儲值改為**客人自願**（想累積/享優惠再儲）。

## 4.5 開桌方式：櫃台報到 + 雙軌開桌（不變）

### 為什麼在櫃台完成（不用自助掃桌碼）
麻將「湊滿四人才能開」，本來就有等人到齊的過程，櫃台是天然的集合／調度中心。店員報到的同時就在做配桌撮合、關係經營，人力不是額外負擔。
- 防逃費最穩（沒報到就進不了桌）
- 長輩零障礙（報手機就好）
- 配桌／揪團在櫃台收斂，店員當場撮合

### 報到流程
```
客人陸續到店 → 櫃台報到
  ↓ 店員 POS 開一桌（如 T3）
  ↓ 每來一人，店員逐一確認身分 + 收費：
      · 報手機 → POS 查出會員，或
      · 出示 LIFF 會員碼 → 店員掃 → 認出會員
      · 確認身分 → 收費（配桌150/人 · 包桌依時段）★可點數/現金/混合
  ↓ 觸發桌子啟動（雙軌，見下）
  ↓ 入座開打 → 鏡頭自動掃牌譜 → 收桌自動結算/升段
```

### 身分識別雙軌
- **熟手機**：出示 LIFF 會員碼，店員掃 → 快
- **不熟手機／長輩**：報手機號，店員查 → 簡單
- 完全不用手機者：店員代開會員（手機+姓名，line_user_id 留空）

### 開桌雙軌（系統處理標準、店員處理例外）
- **軌道一 · 滿四人自動開**：四人都報到收費完成 → 系統判定滿四 → 自動啟動（標準，80%）
- **軌道二 · 店員手動開**：店員按「開桌」，人數由店員判斷 → 啟動。適用三人先打／等補位／代打／VIP通融／系統誤判（例外，20%）
- 精神：系統處理標準、人處理例外，店員保有最終裁量權

### 計費與雙軌的對齊
- 自動開（滿四）：配桌收四人各150；包桌收整桌（400/600/800）
- 手動開（不滿四）：配桌收在場幾人（中途補到的加入時收100）；包桌一樣整桌（按桌不按人）

### 桌子啟動 = 電控連動（分階段）
- **第一階段（開店）**：不接電控，店員確認收費完成後手動放行，先把流程跑順
- **第二階段**：接電控（場域電控硬體或智慧插座／繼電器），做到「收費完成 → 桌子自動啟動」。買一般好桌 + 外加電控，不必買特殊桌
- 進場嚴格（收費才開）、退場溫和（超時前10分提醒，不硬斷電）

## 5. ★金流鐵則 v2.0（取代 v1.0「一律轉點數」）

**v1.0 舊鐵則已作廢**：不再要求「所有付款先轉點數，無一例外」。
**v2.0 新鐵則三條**——付款方式放開了，但這三條不可破：

### 鐵則一：一律會員，無一例外 ⭐
**不管用什麼付款（純現金也一樣），消費者一律要是會員。**
- 純現金客人也要建會員（店員可代開：手機+姓名，line_user_id 留空）
- 為什麼：消費累積要進 CRM、牌咖關係要記錄、店員業績要歸因、段位成績要掛人。**沒有會員 = 資料斷掉，這家店的核心價值（關係經營＋數據）就廢了**
- 這條是 v1.0「一律轉點數」真正想守的東西——現在直接守它本身，不繞路

### 鐵則二：一律入帳，現金也不例外 ⭐
**每一筆收款都要在 POS 記錄（order_payments 記 method='cash'/'credit_card'/'line_pay' + 金額 + 實收找零），沒有「私下收現金」的路徑。**
- 為什麼：帳務完整、報表正確、店員業績算得出來、對帳查得到
- 現金結帳要走收銀確認（實收／找零），不是口袋進出

### 鐵則三：賭資不上桌 ⭐
**牌桌上的輸贏籌碼，與 MIGI 系統完全無關；MIGI 只收場地使用費與商品費用。**
- 檯費＝場地使用費，可收現金（正常服務收費）
- 但 MIGI 不經手、不記錄、不抽成任何牌桌輸贏
- 券只折 MIGI 的服務費，永不折牌桌輸贏

### 點數的新定位
- 點數不再是必經之路，而是**付款選項＋會員經營工具**
- 客人願意儲值 → 給誘因（儲值優惠、等級加速），但**不強迫**
- 1 點 = 1 元，點數不可兌現（這條不變）

---

## 6. 法規守線（更新）

- **賭資不上桌** = 法規護城河（MIGI 只收場地費與餐飲商品費，不碰輸贏）
- 檯費收現金合法正常（場地使用費就是一般服務業收費）
- 所有收款有完整紀錄（鐵則二），可查可對帳
- 點數為預收款性質（儲值時記入預收負債），消費時沖銷；點數不可兌現

- **桌狀態機**：空桌 → 開桌（計時／計將中）→ 超時提醒 → 收桌 → 結算 → 空桌
- 每桌記錄：桌號、模式（配桌／包桌）、成員、開始時間、將數／時段、促成店員
- **★open_session_tx ＝待開發（全新，非修改）** ⚠️
  - **實作真相（2026-07-13 查證）**：`open_session_tx` **從未被建立**，資料庫中不存在。文件過去把它列為「待接」，容易誤解成「改既有函式」——實際是**全新開發**，工時估算請以新建計算。
  - 規格：建 table_session（status=open）+ 綁 session_players + **收費走 tender 模型（點數／現金／混合）** + 更新 tables.status，冪等。
  - **已存在可用的**（2026-07-13 查證）：`checkout_tx`（結帳主函式，已是 tender 模型、已改用 unit_price）、`charge_matched_tx`（配桌收費）、`charge_private_tx`（包桌收費）、`settle_session_tx`（收桌結算）。開桌收費可直接複用 checkout_tx 或 charge_* 系列，不必重寫收費邏輯。
- **★POS 結帳頁要做付款方式選擇**：點數用多少 + 現金收多少 + 實收找零確認
- 中途加入、超時補收 → 獨立收款事件
- 收桌 → 觸發消費累積／成績／店員歸因三項更新
- 商品與定價：檯費商品在總部後台 products 管（SER- 前綴）；包桌階梯在 pricing_tiers 管
