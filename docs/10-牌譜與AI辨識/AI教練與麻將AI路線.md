# MIGI AI 教練與麻將 AI 路線 v0.1

> **這是什麼**：「能不能做一個麻將版的 AlphaGo，用來檢討我的牌局、甚至跟我對弈」的技術評估與落地順序。
> **什麼時候讀它**：討論 AI 教練、逐手重播、對弈功能之前。
>
> 📄 **這一類的既有文件全部在講「怎麼把牌看懂」**（`台麻AI辨識實作指南`、
> `牌譜鏡頭安裝規格`、`牌面編碼對照表`）與「看懂之後算什麼」（`牌譜統計維度規格`）。
> **這一份接在它們後面**：資料有了之後，怎麼變成「你那張該不該打」。

---

## 一句話結論

**可以做，而且不用從零開始 —— 但它跟圍棋是兩種不同的難題，
而 MIGI 真正的瓶頸不是 AI，是資料。**

⚠ 而「資料」那一格**正是路線圖 M4 在做的事**（`paipu_events`）。
順序沒有排錯，只是要知道：**牌譜要累積時間**，不是辨識做完隔天就有教練。

## 一、為什麼 AlphaGo 那一套不能直接搬

| | 圍棋 | 麻將 |
|---|---|---|
| 資訊 | **完全公開**，棋盤上就是全部 | 🔴 **不完全**：看不到別人的手牌與牌山 |
| 隨機 | 沒有 | 🔴 摸牌是隨機的 |
| 一局的結論 | 勝負分明，可直接當訓練訊號 | 🔴 **打得好也可能輸** |

🎯 **第三點才是關鍵。** AlphaGo 的自我對弈之所以有效，是因為
「這一手好不好」最後可以由「這一局贏沒贏」回答。
**麻將不行** —— 一局的結果有巨大的隨機成分，
要**幾千局**才分得出「他比較強」還是「他比較幸運」。

📌 這也是為什麼日本麻將界不用「勝率」而用**平均順位／連對率／トップ率** ——
CLAUDE.md 的「三種分」那一節記的是同一件事：
**四人麻將的「贏」在名次層根本沒有定義。**

⚠ 所以麻將 AI 的訓練必須額外處理**變異數**（把一局的結果拆成
「這一手的貢獻」與「運氣」），而那正是它比圍棋難的地方。

## 二、已經有人做出來了（所以不用從零開始）

| | 是什麼 | 對 MIGI 的意義 |
|---|---|---|
| **Suphx**（微軟亞洲研究院，2019） | 第一個在天鳳達到高段的日麻 AI | 證明了**做得到**，也公開了方法 |
| **Mortal**（開源） | 日麻 AI，**而且附檢討工具** | 🎯 **那個檢討工具就是你要的東西** |

**Mortal 的用法正是「AI 教練」的原型**：牌譜丟進去，它**逐手**告訴你
「AI 會打哪一張、你打的那一張差多少期望值」。
日本的高段玩家現在就是這樣練的。

📌 Suphx 論文裡有兩個技巧值得記，因為它們是**麻將特有的**：

- **Oracle guiding** —— 訓練初期讓 AI **看得到別人的手牌**（開天眼），
  學會「什麼是好決策」之後再逐步把資訊拿掉。
  ⚠ 直接在不完全資訊下從零學，收斂會非常慢。
- **把「這一局的結果」換成「這一整場的期望」** —— 直接用單局勝負當訊號
  會學到噪音（見第一節第三點）。

## 三、對 MIGI 的兩個硬差別

### ① 🔴 台灣麻將沒有現成的模型

Suphx 與 Mortal 都是**日本麻將**，而兩者的差異大到不能遷移：

```
手牌        台麻 16 張        日麻 13 張
花牌        台麻有 8 張       日麻沒有
立直/寶牌   台麻沒有          日麻的核心機制
計分        台麻算「台」      日麻算「符 × 翻」
連莊        規則不同
```

⇒ **要重新訓練，而那不是調參數，是重做。**
⚠ 但**方法可以照抄**（oracle guiding、變異數處理、網路架構），
省下來的是研究時間不是工程時間。

### ② 🔴 真正的瓶頸是資料，不是 AI

```
Mortal 訓練用的牌譜        數千萬局
MIGI 現在的 paipu_events   0 筆（表都還沒建）
```

⚠ 而且**一間店累積不出那個量級**。七間店滿場，一天大概幾百局 ——
要到百萬局是**年**的單位。

🎯 **所以「自己訓練一個模型」不是第一步，是第三步。**

## 四、三層路線（前兩層不需要任何模型）

### L1 · 規則式教練 —— 🎯 **這一層今天就做得到，只要有 `paipu_events`**

不需要模型，只需要**牌理**（那是可以寫成程式的規則）：

```
· 危險牌提示        這張對下家有多危險（他打過什麼、副露了什麼）
· 聽牌判斷          你現在聽什麼、剩幾張
· 有效牌統計        打這張之後進張數變多還是變少
· 明顯的失誤        打掉自己聽的牌、拆掉已成的順子
```

⚠ **不要小看這一層** —— 對絕大多數客人來說，
「你剛剛打的那張，下家已經摸走兩張了」比「期望值差 0.3」有用得多。

### L2 · 統計式教練 —— **用自家的牌譜，不用別人的模型**

```
「這種局面（聽牌、剩 4 巡、對手已副露兩組），
  店裡的客人有 62% 選擇收手，而收手的那些人平均順位比較好」
```

🎯 **這一層是 MIGI 獨有的**：它用的是**你自己客人的資料**，
而那份資料 Mortal 沒有、天鳳也沒有。
📌 而它同時是**社交題材**（「你的打法跟店裡的高手像不像」）——
那比純粹的正確率更有黏著度。

### L3 · 模型式教練 —— 真的訓練一個台麻 AI

**觸發條件（三個都要成立）**：

```
① paipu_events 累積到有意義的量（至少數十萬局）
② 有人專職顧它（硬規則 5.5：需要有人每週維護的功能，先確認那個人存在）
③ L1／L2 已經上線，而且客人真的在用
```

⚠ **第 ③ 條最重要**：如果規則式教練上線後沒人看，
那麼「更準的教練」也不會有人看 —— **問題不在準確度，在需求。**

## 五、「線上對弈」為什麼排最後

使用者提到「甚至可以線上跟我對弈」。技術上是同一個模型，
但**它比檢討難得多，而且價值低得多**：

| | 檢討 | 對弈 |
|---|---|---|
| 何時算 | **事後**，可以慢慢算 | 🔴 即時，每一手幾百毫秒 |
| 算錯的代價 | 建議差一點 | 🔴 對手行為怪異，客人立刻發現 |
| 客人要的 | 「我那張到底該不該打」 | 「有人陪我打」—— **而 MIGI 的核心是真人在同一張桌上** |

🔴 **而最後那一列是決定性的**：MIGI 賣的是**實體牌桌與人的連結**
（`牌搭關係與護城河戰略`）。做一個線上 AI 對手，
等於做一個**跟自己的核心生意競爭**的東西。

⇒ **對弈不做**，或只當成「練習模式」的小功能，不投入模型資源。

## 六、與既有文件的關係

```
牌桌鏡頭安裝規格      怎麼把牌拍下來
台麻AI辨識實作指南    怎麼把影像變成牌面      ← YOLO，跟教練無關
牌面編碼對照表        牌面怎麼存
牌譜成績資料中台      paipu_events 的 schema
牌譜統計維度規格      L0/L1/L2 三層統計
本文件                資料有了之後，怎麼變成建議
```

⚠ **辨識與教練是兩個獨立的難題**，不要混在一起排程 ——
辨識做完只代表「資料開始長」，教練還要等資料長夠。

## 七、現在該做的事：什麼都不做

🎯 **這一份的結論是「先不要動」**，而理由不是保守：

```
L1 需要 paipu_events   → 表還沒建（M4）
L2 需要一定量的牌譜     → 同上
L3 需要 ①②③ 三個條件  → 一個都還不成立
```

✅ **唯一現在該做的是不要把路堵死**：
- `paipu_events` 的 schema 要**逐手可重播**（`turn_no` / `action` / `tile` / `confidence`
  已經在 `牌譜成績資料中台技術設計` 裡了 ✅）
- 辨識的 `confidence` 要留著 —— **教練要知道哪一手是猜的**
- 不要為了省空間丟掉「沒有胡牌的那些局」——
  🔴 **教練最有價值的資料正是失誤，而失誤多半發生在沒胡的局**

📌 **觸發點**：`paipu_events` 開始有資料的那一天，回來看第四節的 L1。
