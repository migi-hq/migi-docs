# 當日 Re-ID 座位比對 — 具體實作方式

> **這是什麼／何時讀**:「櫃檯報到的人跟桌邊東南西北座位的人是不是同一人」這個比對要怎麼做的技術細節與程式骨架。要動手實作自動座位比對(認牌主線驗證通過之後)時讀這份。政策層決策(為何不建人臉資料庫、個資同意方式)見《牌譜成績資料中台技術設計》§10.5,本文是它的實作補充。

## 核心概念

把「一個人的影像」變成一串數字(特徵向量,例如 512 維),同一人的兩張照片向量會很接近,不同人會差很遠。「認同一人」= 算兩串數字的相似度,超過門檻就判定同一人。這叫 **重識別(Re-ID)**,跟「認出這是誰」的人臉辨識資料庫是不同任務——Re-ID 只問「A 是不是等於 B」,不需要知道 A 是誰。

**這正是採用它的原因**:身分永遠由櫃檯掃碼確定,Re-ID 只負責「櫃檯這位 = 座位這位」的比對,不需要、也不建立長期人臉資料庫。

## 為什麼比對範圍小很多,天生比人臉辨識準

- 一般人臉辨識(1:N,N 是全會員庫,幾百到幾千人)要從一大群人裡認出一個,N 越大越容易認錯。
- 當日 Re-ID 的比對範圍只是「今天報到的十幾二十人」,開桌後更縮小到「這桌 4 人」(1:4)。**範圍越小,準確率天生越高。**

## 管線(四步)

1. **偵測人**:YOLO 現成就能框出「person」(通用模型內建,不需額外訓練,可與認牌用的 YOLO 共用推論框架)。把人形裁下來。

2. **轉向量**:裁下來的人形圖丟進 Re-ID 模型,吐出一條特徵向量。推薦：
   - **人形 Re-ID**:OSNet(`torchreid` 套件內建預訓練權重)——看整體衣著、體型、輪廓,**側面、背面也認得出**,適合角櫃鏡頭拍不到正臉的情境。
   - **人臉 Re-ID**:ArcFace 類——拍得到正臉時準確率最高,可與人形模型並用互補。

3. **建當日名單**:櫃檯報到掃碼那刻(身分已由掃碼確定),連拍 3~5 張、各轉向量取平均,存成 `{member_id: 向量}`,只放記憶體或當日暫存,**不落地存檔**。

4. **桌邊比對**:角櫃鏡頭看到座位上有人 → 同樣偵測 + 轉向量 → 跟今日名單逐一算 **cosine 相似度** → 最高分且超過門檻 → 判定「東位 = 雅琪」→ POS 顯示待確認,店員/玩家一鍵確認後才寫入 `game_players`。

## 程式骨架

```python
import torchreid
import numpy as np

extractor = torchreid.utils.FeatureExtractor(model_name='osnet_x1_0')

def cos(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# 報到時:建立今日名單(每位會員存平均向量)
today = {}  # {member_id: vector}
vec = extractor([checkin_crop])[0]
today[member_id] = vec   # 多張取平均更穩

# 桌邊比對
vec = extractor([seat_person_crop])[0]
sims = {mid: cos(vec, v) for mid, v in today.items()}
best_id = max(sims, key=sims.get)
best_score = sims[best_id]
```

## 三個實戰要點

1. **門檻 + 差距雙保險**:不只要最高分過門檻(例如 0.7,須實測調整),還要第一名比第二名**拉開明顯差距**(例如高 0.1 以上)才採信,否則標記「不確定,請人工確認」——這是防止「兩個人穿同款黑衣」誤判的關鍵。

2. **比對範圍分層縮小**:入座前用「今日全店報到名單」比對;開桌後範圍縮到「這桌 4 人」,準確率再拉高。

3. **中途換外套會掉準度**——這是人形 Re-ID 的天生弱點。解法就是半自動設計本身:認不出就退回人工指定,不硬猜。

## 個資與生命週期

- **當日打烊 → 特徵向量全數清空**,不落地存檔,不留存。
- 縱使當日即刪,拍攝與處理仍屬生物特徵資料處理,**報到時須告知並取得同意**(「僅當日自動入座使用、打烊即刪」)。
- 拒絕者掃碼照常消費,座位改手動指定,功能不強制。

## 落地順序

**非主線**,優先序低於牌譜辨識(認牌)。YOLO、Python 環境、標註流程在認牌主線都會用熟,屆時加這條 Re-ID 管線大概是一兩天的工作量,不是一個新專案。
