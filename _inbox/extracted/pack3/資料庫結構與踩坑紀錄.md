# 資料庫結構要點與踩坑紀錄

> 這是什麼：實際查證過的資料表結構、關鍵約束、以及開發時踩過的坑。
> 什麼時候讀：寫任何 SQL 之前，特別是要 UPDATE 狀態欄位或改函式簽名時。

---

## 一、關鍵表結構（已查證）

### `table_sessions`

```
id, org_id, store_id, table_id, mode(enum), status(text),
planned_rounds, planned_minutes, opened_by,
started_at, ended_at, created_at,
stake_level_id, activated_at, game_type, flower, is_test
```

**沒有 `closed_at`，收桌時間欄位是 `ended_at`。**

status 的 check constraint：
```sql
CHECK (status = ANY (ARRAY['open', 'completed', 'voided']))
```
是 **`voided`** 不是 `void`。

### `tables`

```
id, org_id, store_id, label, area, seats, status?, sort, is_active, created_at
```

**⚠ 實測 `SELECT status FROM tables` 會報 "column does not exist"**，資料庫提示「Perhaps you meant tables.seats」。
因此 **POS 桌況是從 `table_sessions` 動態算的**（有無 open 場次），不是讀 `tables` 的欄位。
要釋放卡住的桌位，作廢 session 即可，不需要也不能 UPDATE `tables.status`。

### `session_players`

原有欄位加上代付支援：
```
+ paid_by uuid REFERENCES members(id)   -- null=自己付；有值=由該會員代付
```
判斷規則：有 `order_id` = 自己結過帳；有 `paid_by` = 被代付。
兩者皆無理論上不會發生（`join_session_tx` 是結帳同時入座）。

### append-only 保護

`app_events` 與 `wallet_txns` 都有觸發器禁止 UPDATE/DELETE：
```
ERROR: P0001: app_events 為 append-only，不可刪改
CONTEXT: PL/pgSQL function app_events_no_mutate()
```
**不要試圖回填或清除這兩張表**，改用 view 動態過濾。

## 二、SQL 鐵則

### 改函式簽名必須先 DROP

PostgreSQL 把不同參數數量視為不同函式，`CREATE OR REPLACE` **不會覆蓋舊版**，會變成新舊並存，呼叫時可能打到舊的。

同一份 SQL 必須附：
```sql
DROP FUNCTION IF EXISTS public.函式名(舊參數型別清單);
```

已在 `register_member_tx`、`calc_session_fee_tx`、`join_session_tx` 各踩過一次。

**驗證方式**：
```sql
SELECT count(*), string_agg(pronargs::text, ',')
  FROM pg_proc WHERE proname = '函式名';
-- 應回「1 個」，多於 1 代表新舊並存
```

### POS 用 anon key 無 session

`current_org_id()` 回 null → 直接 `supabase.from('表').select()` **查詢成功但回空陣列且不報錯**（最難察覺的失敗模式）。

**POS 與 App 所有查詢一律走 SECURITY DEFINER RPC。**

## 三、Vite / 部署鐵則

- Vite build hash 含底線（如 `index-57-_FGWz.js`）→ LINE WebView 載入失敗 → 必須設 `hashCharacters: 'hex'`
- `_headers` 只擋 `/index.html` 會漏掉根路徑 `/`（LINE 實際載入的是根路徑）→ 必須同時擋 `/` 這條，但**不要用萬用 `/*`**（會造成 MIME 事故）
- 新增元件檔案沒進 repo 會白屏，但電腦與 LINE 都白；**電腦好 LINE 壞 = 快取層問題**

### 白屏排查 SOP

1. 先分辨純白 vs 🐻卡＋看版本號
2. 三 URL 交叉定位（`migi-web.pages.dev` ／ 電腦 Chrome `app.migi.tw` F12 ／ LINE 開 `version.json`）
3. 查 `app_events` 有無 `app_error`

## 四、前端踩過的坑（POS HTML 原型期）

| 症狀 | 根因 |
|---|---|
| 檯費金額顯示 0 / 「免收」 | `CATALOG.檯費` 改空陣列後 `catalogItem()` 查不到，回傳預設 `price: 0`。需另查 `feeCatalog()` |
| 舊檯費品項刪不掉 | `indexOf('檯費')===0` 判斷失敗（品名是「配桌檯費」，檯費在 index 2）→ 改用 `>= 0` |
| 小計金額虛胖 | 誤含儲值金額 → 改用 `discountable(p)` |
| 按鈕文字不置中 | 兩條 `.payfor-btn` CSS 規則並存，舊的 `display:flex` 讓 `text-align:center` 失效 |
| 代付面板延續到別人身上 | `payForOpen` 是全域狀態，切換座位時未重置 |
| 步進鈕一高一低 | 全形 `＋` 與半形 `−` 基線不同 → 統一半形 + Segoe UI + `line-height:1` |
| 名稱截斷失效 | flex 子元素預設不縮，需同時加 `min-width: 0` |
| 展開時把內容往上推 | 區塊在 `flex-direction:column` 容器底部，變高只能往上長。要往下推須放在可捲動區之上 |

**用正則刪函式時範圍過寬會誤刪後續函式**（`[\s\S]*?\n\}\n` 遇巢狀括號會多吃），已誤刪 `renderMid` 與 `closeTopup` 各一次。改用明確指定完整內容。

- `members.is_test = true` 標記四個測試帳號（電話 0910768736／0910000002／0910000003／0910000004）
