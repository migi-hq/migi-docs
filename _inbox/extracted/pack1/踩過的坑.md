# 踩過的坑（血淚教訓）

**【這是什麼】** 這輪實際撞到並解決的問題，含症狀、根因、解法。
**【何時讀】** 遇到白屏、資料沒更新、部署沒生效時**先讀這份**，八成在裡面。

---

## 1. LIFF 白屏：build hash 含底線

**症狀**：網頁版正常、LIFF 白屏；清快取無效、網址加 `?v=N` 也無效。
**根因**：某次 Vite build 產生的檔名是 `index-57-_FGWz.js`——**hash 含底線 `_`**，LINE WebView 載入這種檔名失敗（`<script type="module" crossorigin>` 相容性問題）。純機率事件，所以「過去一個月密集開發都沒事、這兩天突然炸」。
**解法**：`vite.config.js` 設 `hashCharacters: 'hex'`，強制 hash 只用 0-9a-f，永久排除。

**診斷法（很重要）**：LIFF 白屏時，比對「網頁版原始碼的 JS 檔名」vs「LIFF 報的載入失敗檔名」——
- 檔名**一樣** → 檔案本身在 WebView 載不動（如本例）
- 檔名**不一樣** → 才是快取問題

## 2. `_headers` 是地雷區（有前科，不要碰）

曾用 `public/_headers` 設 `no-store` + 對根路徑 `/` 設規則 → JS 模組請求被回傳 HTML → MIME 錯誤 → 整站白畫面。
**結論：不要用 `_headers` 調快取。** 即使改成 `no-cache`、即使只針對 `.html`，Pages 的匹配行為沒有十足把握，不值得賭第二次。
替代方案：開發期手動清 LINE 快取；正式的根治是 content hash（已由 Vite 對 JS/CSS/圖片全面處理）。

---

## 3. Cloudflare Pages build 失敗 → 靜默保留舊版

**症狀**：push 了好幾次，線上畫面完全沒變（CSS 改動、圖片換新都沒生效）。
**根因**：`src/assets/` 圖片沒放進 repo → build 報 `Could not resolve "../assets/bear-lv1.webp"` → **Pages build 失敗時保留上一次成功的版本**，所以你以為部署了，其實一直在跑舊版。
**解法／SOP**：**push 完瞄一眼 Cloudflare Pages → Deployments 列表是綠色 Success 還是紅色 Failed。** 紅的就代表沒上線，點進去看錯誤訊息。這一步能省下大量「為什麼沒更新」的鬼打牆。

---

## 4. 圖片換了不更新（固定檔名快取）

**症狀**：覆蓋 `public/snack-cookie.webp` 換新圖，部署後畫面還是舊圖。
**根因**：`public/` 的檔案是原樣複製、**檔名固定**，內容改了檔名沒變 → 瀏覽器直接用快取。
**根治（已做）**：圖片全部移到 `src/assets/`，改用 `import` 引用（集中在 `src/lib/images.js`）。Vite 會給圖片加 content hash（`snack-cookie.a3f9c2.webp`），內容一改檔名自動變，永不咬快取。
**規矩**：新圖放 `src/assets/` 並在 `images.js` 註冊 import，**不要放 `public/`**。
（例外：`public/default-avatar.svg` 仍是舊做法，哪天要換它記得比照搬遷。）

---

## 5. 元件沒 import 就使用 → build 過但點了就 crash

**症狀**：`npm run build` 完全正常，但點某顆按鈕整頁白。
**根因**：JSX 用了未 import 的元件/函式（如 `SettleSheet`、`track`），**打包器不會擋未定義的執行期識別字**，只有真正執行到才炸。
**發生過兩次**：①`App.jsx` 用 `SettleSheet` 但沒 import ②清 import 時把還在用的 `track` 一起刪掉。
**預防**：刪 import 前全檔搜尋該識別字；改完關鍵路徑實際點一次。

## 6. `wallet_txns` 是 append-only，刪不掉

**症狀**：`delete from wallet_txns` 報錯
`ERROR: wallet_txns 為 append-only 帳本,不可 UPDATE/DELETE;退款請新增 reversal 分錄`
**根因**：`block_txn_mutation()` 觸發器（正確且嚴謹的財務設計）。
**結論**：帳本只進不出。錯誤交易用**沖正**（`reverse_txn_tx`）抵銷，測試帳號用 **`is_test` 標記隔離**，都不要刪。
（`app_events` 同樣有 append-only 保護，但 `truncate` 可繞過，測試期歸零可用。）

---

## 7. anon key 查詢「成功但回空陣列」

前端用 anon key 沒有 session → `current_org_id()` 回 null → 直接 `supabase.from('表').select()` **不報錯、回空陣列**，是最難察覺的失敗模式。
**鐵則：所有查詢一律走 SECURITY DEFINER RPC。**

---

## 8. 改函式簽名時 `CREATE OR REPLACE` 不會覆蓋舊版

PostgreSQL 把不同參數數量視為不同函式。增減參數時**同一份 SQL 必須附 `DROP FUNCTION IF EXISTS public.函式名(舊參數型別清單)`**，否則新舊版並存、呼叫端可能打到舊的。
