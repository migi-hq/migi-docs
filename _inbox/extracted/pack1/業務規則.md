# 業務規則（產品邏輯規格）

**【這是什麼】** 牌咖、配桌、黑名單、按讚的完整流程規則，實作與驗收都以此為準。
**【何時讀】** 寫 RPC、改前端流程、或驗收功能行為時。

---

## 牌咖流程

**入口限制**：只有**同桌對局過**的人才會出現「加牌咖」入口。
兩個入口：
1. **收桌視窗** — 打完牌跳出，同桌者列表每人可按讚 + 加牌咖
2. **牌咖區「最近同桌」** — 保留 **1 天**，錯過就沒有（限時製造當下決定的動力）

**邀請與回應**
1. 我發出邀請 → 我的按鈕變「已邀請」
2. 對方收到：通知中心一則 + 牌咖區頂部橫向提示欄（兩處同步）
3. **拒絕** → 對方跳 toast「已拒絕（對方不會收到通知）」，**我完全無感**（無痕）
4. **接受** → 對方跳 toast；我下次回來通知看到「XXX 已接受」；我的牌咖列表最上方出現他 + 「新加入」pill

**牌咖列表**：每人只有「查看」按鈕（揪桌入口已移到配桌頁，見下）。

## 揪牌咖（簡化後的最終版）

**揪的入口只在配桌情境**，其他地方（牌咖列表、檔案卡、成為牌咖視窗）都沒有揪按鈕。

| 入口 | 行為 | 埋點 mode |
|---|---|---|
| 開桌設定區「＋ 邀牌咖一起」 | 可多選勾人，**開桌成功瞬間**自動全部送出邀請 | `auto_after_open` |
| 配桌等待卡「＋ 邀牌咖加入這桌」 | 開名單，點誰立即邀誰 | `direct` |

對方視角：通知/提示欄收到揪桌邀請 → 拒絕無痕 / 接受自動入桌。

## 配桌時間模型

- **`play_at`（預定開打時間）是唯一時間錨點**，由開房者指定。
- waiting 到 `play_at` 仍未滿員 → `expired`。
- **成桌後永不自動解散**；沒到的人由**店員手動標 `no_show`**。
- 理由：每人到店路程不同，固定倒數對住遠的人不公平。
- 店員/房主可改 `play_at`（喬時間）並通知房內全員。

## 黑名單（四道防線）

**原則**
- 單向紀錄、**雙向生效**（A 黑 B → 互相看不到、互相進不去）
- **訊息模糊化**：一律「此桌已無法加入」「無法邀請此牌咖」，與桌滿/解散同語氣，永不洩漏黑名單存在
- 黑掉牌咖 → 自動解除牌咖關係 + 作廢未回覆邀請 + 清理相關通知

**四道防線**
1. **列表過濾** — `list_match_queues_tx` 排除「房內任一人與我互黑」的房（ABC 三桌只顯示 B）
2. **加入時鎖內檢查** — `join_match_queue_tx` 在 `FOR UPDATE` 鎖房**之內**再驗一次。
   這是**時間差場景的最終防線**：對方 App 因輪詢延遲還顯示著我在的房，他按加入 → 伺服器擋下。
   *畫面只是視覺，伺服器才是真理。*
3. **邀請時檢查** — 受邀者 vs 房內全員互黑 → 「無法邀請此牌咖」
4. **接受邀請時再檢查** — 邀請發出後房內可能又進了互黑者，接受時複用第 2 道

**延伸**：拉黑後，該人應從我 App 的**所有社交表面消失**（最近同桌、收桌按讚對象、牌咖列表）。
**已同房時拉黑**：不自動踢任何人（避免被當攻擊工具），改為詢問拉黑者本人「要退出這桌嗎？」。
**空列表 UX**：被過濾到一桌不剩時顯示通用文案「目前沒有適合你的牌桌，開一桌吧！」，不可顯示「有 N 桌被隱藏」。

## 按讚

- 指標定案為 **👍 讚**（線條 icon，非 emoji；曾評估愛心/紅中等方案）
- 入口：收桌視窗每位同桌者旁的圓鈕，可按可取消
- 顯示：個人檔案與他人檔案卡的 **Hero 右上角** pill（線條讚 icon + 數字）
- 後端：`like_player_tx` 防重複（同局同人一次；無 session 過渡期為同人同日一次），同步維護 `members.likes_count`

---

## 稱號與段位顯示

- **稱號**：純文字加引號「新手上路」，深墨黑字，位於名字上方（無 pill、無箭頭）
- **段位**：pill 樣式，格式 `段位: 銅牌熊 I`（全 App 統一，由 `fmtRank()` 產生）
- 七階段位熊圖：銅牌/銀牌/金牌/白金/鑽石/大師/雀神

## 店員兜底（POS 端配合需求）

1. 店員開桌選人時，名單含**互黑會員要跳警示**建議分桌（線上防得再好，線下排桌會破功）
2. 店員可對**未滿房強制成桌 + 代打補位**讓桌準時開
3. 代打局的店員成績，M4 段位結算時排除
4. 被人工介入的桌，M3 分析「自然成桌速度」時排除（否則店員越勤勞、數據越失真）
