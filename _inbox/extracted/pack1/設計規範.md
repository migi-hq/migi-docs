## 圖片資源管理

**規矩：圖片放 `src/assets/`，在 `src/lib/images.js` 註冊 import，不要放 `public/`。**

理由：`public/` 是原樣複製、檔名固定 → 換圖不更新（快取問題）。
`src/assets/` 走 Vite，自動加 content hash（`snack-cookie.a3f9c2.webp`），內容改則檔名變，永不咬快取。

現有資源（17 張 webp）：
- 養成熊三階段 `bear-lv1/10/20`（目前三階同圖）
- 段位熊七階 `bear-rank-bronze/silver/gold/platinum/diamond/master/quegod`
- 教練熊 `coach-bear`（限時活動）
- 甜點六種 `snack-cookie/milktea/pudding/tiramisu/cupcake/donut`

**換現有圖**：覆蓋 `src/assets/` 同名檔即可，程式不用動。
**加新圖**：放進去 + `images.js` 加一行 import + 註冊到對應的匯出物件。

段位熊圖片處理心得：AI 生成的圓形常是微橢圓（高多 3–6%），需垂直微縮回正圓、並統一圓直徑佔比（480/512）才不會並排時大小不一。

## 建置設定（`vite.config.js`）

```js
build: {
  target: 'es2015',              // LIFF 舊 WebView 相容，轉譯 ?. ?? 等新語法
  rollupOptions: { output: {
    hashCharacters: 'hex',       // ★必須：底線 hash 會導致 LINE WebView 白屏
    entryFileNames: 'assets/[name].[hash:8].js',
    chunkFileNames: 'assets/[name].[hash:8].js',
    assetFileNames: 'assets/[name].[hash:8][extname]',
    manualChunks: { vendor: ['react','react-dom','@supabase/supabase-js'] },
  }},
},
define: { __APP_VERSION__: ... }  // 版本號注入，格式 vMMDD-HHmm（台北時間）
```

**vendor 分離效果**：JS 從一顆 570KB 拆成 vendor 363KB（幾乎不變）＋業務碼 232KB，
改業務碼時使用者只需重抓小的那顆。

**版本號**：設定頁底部顯示（照 LINE / 銀行 App 慣例），埋點事件也帶 `app_version`。

## UI 慣例（既有規範，沿用）

- **容器三型**：抽屜 DragSheet（看完就關）／切頁（深度內容）／中央彈窗（事件時刻）
- **按鈕層次**：墨底白字＝主動作（一區塊最多一顆）／淺灰底墨字＝次要／淺灰底淡字＝婉拒／白底墨框＝替代主動作
- **卡片邊框**：主要互動用 `--brand`；系統性/次要用 `--field-bd` 配 `--field-bg`
