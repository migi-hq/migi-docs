# 資料表結構速查

> **這是什麼**：MIGI 資料庫實際欄位與 CHECK 約束的速查表，全部經 SQL 查證，非規劃值。
> **什麼時候讀**：寫任何 SQL、RPC、前端資料存取之前。碰既有表前先查約束是鐵則——過去多次因為沒查就寫而踩坑（not null 沒給值、category 填錯被 check 擋）。
> 查證日期：2026-07~08。若資料庫又有變更，以線上實查為準。

---

## products（商品）

| 欄位 | 型別 | 可空 | 說明 |
|---|---|---|---|
| id | uuid | NO | gen_random_uuid() |
| org_id | uuid | NO | 多租戶隔離 |
| sku | text | NO | 貨號，三段式，見《商品與貨號規範》 |
| name | text | NO | 品名 |
| category | text | NO | **service / fnb / merch**（check 約束） |
| unit_price | bigint | NO | **售價（元）**。原名 unit_points，2026-07-12 更名 |
| unit_cost | bigint | — | 成本（元） |
| is_active | bool | — | 在不在菜單（上架／下架） |
| is_available | bool | — | 現在有沒有貨 |
| stock_qty | int | — | 庫存數量（>= 0 check） |
| deleted_at | timestamptz | YES | 軟刪除 |
| created_at / updated_at / created_by / updated_by | | | 審計欄 |

**CHECK 約束**
- `products_category_check`: category IN ('fnb','merch','service')
- `products_stock_qty_check`: stock_qty >= 0
- `products_unit_price_check`: unit_price >= 0

## order_items（訂單品項）

| 欄位 | 型別 | 可空 | 說明 |
|---|---|---|---|
| id | uuid | NO | |
| order_id | uuid | NO | FK → orders，**ON DELETE RESTRICT** |
| product_id | uuid | NO | FK → products，**ON DELETE RESTRICT** |
| org_id | uuid | NO | |
| name | text | YES | 下單當時的品名快照 |
| kind | text | YES | **fee / fnb / goods**（check，允許 null） |
| qty | int | NO | 預設 1，> 0 check |
| unit_price | bigint | **NO** | 單價（元） |
| line_total | bigint | YES | qty × unit_price |
| created_at | timestamptz | NO | |

> **重要**：此表**不存 sku**，只存 product_id 與 name 快照。因此改商品 SKU 不影響歷史訂單，但也代表用 SKU 做報表時，歷史資料會跟著商品當下的 SKU 走。
> 舊欄位 `unit_points` 已於 2026-07-12 刪除（元計價遷移）。

## staff（員工／總部人員）

| 欄位 | 型別 | 可空 | 說明 |
|---|---|---|---|
| id | uuid | NO | |
| org_id | uuid | NO | |
| store_id | uuid | YES | 總部人員留 null |
| auth_uid | uuid | YES | 對應 Supabase Auth 的 user id |
| name | text | NO | |
| role | text | NO | 預設 'floor' |
| deleted_at | timestamptz | YES | |

**CHECK**：`staff_role_check`: role IN ('floor','manager','hq','owner')

> `members` 是會員（客人），`staff` 是員工。`current_org_id()` 先查 staff.auth_uid，再查 members.line_user_id。
> **HQ 管理員必須在此表有一筆資料**（role='hq'），否則 current_org_id() 回 null，讀寫全被 RLS 擋。

## table_sessions（牌桌場次）

**既有 CHECK 約束（實查，非規劃值）**
- mode: **'matched'（配桌） / 'private'（包桌）**　← 不是 'match'
- status: **'open' / 'completed' / 'voided'**　← **沒有 'playing'**

**2026-08-07 新增欄位**
| 欄位 | 說明 |
|---|---|
| planned_rounds | 配桌預定將數（2 或 3），包桌為 null |
| planned_minutes | 包桌預估時長（120／300／1440），配桌為 null |
| opened_by_staff_id | FK → staff |
| activated_at | 實際開打時間。**null=收費報到中，有值=已開打** |
| idempotency_key | 冪等鍵（正式欄位，非借用 note） |

**唯一索引**
- `uq_sessions_idem` ON (idempotency_key) WHERE idempotency_key IS NOT NULL
- `uq_sessions_open_table` ON (table_id) WHERE status='open' AND deleted_at IS NULL

> **狀態設計**：場次沒有獨立的「進行中」狀態，用 activated_at 是否有值區分。
> 這樣不必擴充 status 約束，而 activated_at 本來就要記（日後接電控用）。

## 其他已查證存在的欄位

寫 RPC 時可安心使用：

- `orders`: session_id, table_id, channel, entity_id
- `stores`: entity_id
- `members`: display_name, rank, avatar_source, avatar_photo_path, line_user_id
- `tables`: label, area, is_active, org_id, store_id
- `stake_levels`: label
- 函式 `_blocked_between(org, member_a, member_b)`：互黑判斷

## pricing_tiers（計費級距，目前閒置）

原設計：mode='matched' 用「將數」級距、mode='private' 用「分鐘」級距，可用 store_id 做分店覆寫。
**現況：此表為空，且已無函式引用**（舊的 charge_matched_tx / charge_private_tx 已封存）。
檯費改以 products 管理。該表暫留，日後若需要「分店覆寫價格」再啟用（products 無 store_id 維度）。
