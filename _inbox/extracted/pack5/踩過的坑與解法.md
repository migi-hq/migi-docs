# 踩過的坑與解法

> **這是什麼**：實際踩過並解決的技術陷阱，每一條都有明確病因與修法。
> **什麼時候讀**：遇到白畫面、權限錯誤、SQL 報錯時先來這裡找；動 RLS、部署、拆檔之前也該掃一遍。
> 這些坑都花過數小時排查，重複踩的成本很高。

---

## 一、Supabase RLS

### 1. `stack depth limit exceeded`（讀取 500）

**病因**：RLS policy 用了 helper 函式 `current_org_id()`，該函式查 staff/members 找 org，但**沒有 SECURITY DEFINER** → 查表時受 RLS 限制 → 觸發那些表的 policy → policy 又呼叫 current_org_id() → 無限遞迴。

**修法**
```sql
CREATE OR REPLACE FUNCTION public.current_org_id() RETURNS uuid
LANGUAGE sql STABLE
SECURITY DEFINER              -- 繞過 RLS，斷開遞迴
SET search_path = public      -- 配套安全設定，防注入
AS $$ ... $$;
```

**通則：所有被 RLS policy 引用的 helper 函式，一律要 SECURITY DEFINER + SET search_path。** 這是 Supabase 官方推薦寫法。

### 2. `new row violates row-level security policy`（寫入 403）

兩個原因會同時存在：
- **policy 只有讀取**：`for select` 的 USING 不管寫入。INSERT/UPDATE 要有 WITH CHECK
- **登入帳號不在 staff/members**：current_org_id() 回 null，org_id 對不上

**修法**
```sql
-- (a) 把登入帳號加進 staff
insert into staff (org_id, auth_uid, name, role)
values ('<org>', '<auth user id>', 'MIGI 總部管理員', 'hq');

-- (b) 補寫入 policy
create policy products_org_write on products
  for all
  using (org_id = current_org_id())
  with check (org_id = current_org_id());
```

**通則**：每個要用系統的登入帳號（HQ 管理員、每個 POS 店員）都必須在 staff 表有對應資料。

## 二、PostgreSQL

### 3. `REVOKE` 沒效果——PUBLIC 的預設權限

**病因**：建立函式時 PostgreSQL **預設把 EXECUTE 授予 PUBLIC**，而 anon / authenticated 會從 PUBLIC 繼承。只收回它們的明確授權，仍能透過 PUBLIC 呼叫。

**怎麼看出來**：查 `proacl`，開頭的 `=X/postgres`（等號前空白 = PUBLIC）就是。

**修法**：`REVOKE EXECUTE ON FUNCTION ... FROM PUBLIC, anon, authenticated;`

### 4. `42P13: cannot remove parameter defaults from existing function`

**病因**：用 `CREATE OR REPLACE FUNCTION` 改一支既有函式，但新版沒帶原本的參數預設值。

**修法**：照錯誤訊息的 HINT，先 `DROP FUNCTION IF EXISTS xxx(參數型別列表);` 再 CREATE。

### 5. `array_agg is an aggregate function`

**病因**：用 `pg_get_functiondef()` 掃描函式時，碰到資料庫裡的聚合函式就報錯。

**修法**：改用 `prosrc` 欄位讀函式原始碼，並加 `prokind = 'f'` 排除聚合函式。
```sql
SELECT proname FROM pg_proc
WHERE prosrc ILIKE '%關鍵字%' AND prokind = 'f';
```

### 6. 停用舊函式不要用 CREATE OR REPLACE 覆寫

覆寫會**抹掉原始碼**（無法稽核，註解寫「保留供稽核」是假的），而且可能觸發上面的 42P13。
正確做法：用 REVOKE 撤銷執行權限 + COMMENT 標註停用原因，函式本體完整保留。

## 三、Supabase SQL Editor 操作

### 7. 一次跑多個 SELECT 只顯示最後一個結果

**這是 SQL Editor 的行為，不是出錯。** 三段 SELECT 都執行了，但結果區只顯示最後一段。

**通則（給 Jim 的 SQL 鐵則）**：診斷用 SQL **一份只放一個 SELECT**。要查多樣就拆成多個檔，或用 `UNION ALL` 併成單一結果表。DDL（alter / create policy 等無回傳的）可以多段一起。

## 四、前端部署

### 8. LIFF 白畫面 ── ES2020 語法（已根治）

**病因**：LINE 舊版 WebView 不支援 bundle 裡的 `?.` / `??` 語法，整個 module SyntaxError 靜默死掉，**不觸發 window.onerror，Console 沒紅字**。網頁版正常是因為現代瀏覽器支援。

**診斷法**：index.html 加 inline 除錯器（錯誤 overlay + 版本標記 + 10 秒檢查 root 是否為空）。「看得到標記但 root 是空的」＝ module 根本沒跑 ＝ 語法或載入問題。

**修法**：`vite.config.js` 加
```js
build: { target: 'es2015' }
```
**此設定永久保留不可移除**，移除就再炸。migi-web 與 migi-pos 都已設定。

### 9. ⛔ 絕對不要用 `_headers` 檔設快取

曾加 `public/_headers` 設 `no-store` 且對根路徑 `/` 下規則 → **JS 模組請求被回傳 HTML → MIME 錯誤 → 整頁白畫面**。
解法是刪掉 `_headers` + Cloudflare Purge Everything。

**通則**：不要碰 `_headers`。快取問題用其他方式處理（Purge、版本參數）。

### 10. 拆檔造成白畫面：漏帶依賴

拆 React 大檔時連環踩坑，都是「漏帶東西」：
- 用了 `createPortal` / `useState` 但沒 import
- 元件依賴的子元件還留在原檔沒一起搬
- **最隱蔽的：漏抽 module 級常數**（函式用到的 `MJ_INK` 這類常數留在原檔，執行到才爆 not defined）

**驗證方法（關鍵）**：`esbuild` bundle **抓不到**這類執行期錯誤（它當普通變數，不報錯，渲染才爆）。**唯一可靠的是用 jsdom 真 DOM 環境實際 mount 渲染測試**。

**通則**：抽任何函式／元件前，掃一遍它用到的所有大寫常數是否一起帶走；每個抽出的檔案都要 jsdom 實測渲染。

### 11. 元件的 zIndex 參數

元件內用 `zIndex: z` 但函式簽名漏了 `z` 參數 → undefined → 一渲染就白畫面。

## 五、資料庫遷移

### 12. 改欄位名前，先查誰在引用它

`products.unit_points` 更名時，查到 checkout_tx 內含 unit_points 字樣，一度以為會壞。
實際查證後發現：**那是 order_items 表的欄位，不是 products 的**，而且 checkout_tx 的價格全部來自前端傳入的 JSON，根本不讀 products 表。

**通則**：看到函式裡有同名字串，先確認它指的是哪張表的欄位，不要直接假設。

### 13. 刪欄位的正確順序

要刪 `order_items.unit_points`（not null 舊主欄）時：
1. **先**改 checkout_tx，讓它不再寫入該欄
2. **再**補齊資料、把新欄設 not null、DROP 舊欄

順序反了的話，中間會有一段「函式寫入不存在的欄位」的空窗，結帳全部失敗。

## 六、其他

### 14. 貨號不回收
刪除是軟刪除（資料還在），若回收號碼會撞號，且違反「一個貨號永遠對應同一商品」。
`nextSku` 取現有最大值 +1，刪掉 002 後新增拿到 004。這是業界標準做法。

### 15. Google Fonts 造成的 403
POS 出現 403 但沒接 Supabase——來源是 index.html 載入 Google Fonts 失敗（暫時性）。
已移除該 link，CSS 本就以系統字型優先（`-apple-system, PingFang TC, Noto Sans TC`），外觀幾乎不變且載入更快。
