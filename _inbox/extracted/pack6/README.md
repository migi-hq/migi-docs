# MIGI 麻將連鎖 · 專案資料包

> 這是什麼:MIGI 全專案的最終版產出。舊版、過程討論、失敗嘗試均已剔除。
> 什麼時候讀:接手專案的第一份文件。

## 建議閱讀順序

1. `docs/決策紀錄.md` — 所有拍板決策,一頁看完
2. `docs/資料表總覽.md` — 資料表在哪、放什麼
3. `docs/開桌結帳流程規格.md` + `docs/檯費SKU商品制.md` — 計費(後者為最新)
4. `docs/成桌責任光譜總綱.md` — 客流與護城河總綱
5. `docs/待辦與未定案.md` — 還沒做的事

## 資料夾

- `docs/` — 規格與戰略文件
- `sql/applied/` — 已可部署的 SQL 與後端程式(M0/M1)
- `sql/pending/` — 尚未產出的變更(目前空)
- `assets/` — 原型 HTML、圖檔、簡報、試算表

## 動手前必讀

改任何原型 HTML 前,先讀 `docs/前端原型踩坑筆記.md`。
寫任何資料表或 RPC 前,先讀 `docs/資料架構基石規範.md`(22 項基石)。

## 鐵則

- 繁體中文;台麻用語,日麻用語禁用。
- 點數只收場地費,絕不碰桌上輸贏。
- 餘額一律由 `wallet_txns` 流水推導,絕不直接設。
- Supabase 一律 Dashboard 操作,不用 CLI。

## 檔名說明

「牌搭」= 一起打牌的夥伴(對話中慣稱的另一寫法),檔名採此寫法以避開特定字元造成的下載問題,文件內文用語不變。
