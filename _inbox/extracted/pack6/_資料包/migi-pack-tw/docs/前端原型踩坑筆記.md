# 前端原型:交付方式與踩過的坑

> 這是什麼:做 MIGI HTML 原型時實際踩過的雷與正確做法。
> 什麼時候讀:**動手改任何原型 HTML 之前先讀**,可省下數輪除錯。

## 坑 1:onclick 內的引號跳脫會壞掉

**症狀**:按鈕點了完全沒反應(名人堂、推薦揪團、揪她、扭蛋收下都中過)。

**原因**:用程式拼接 HTML 字串時,`onclick="fn(\'中文參數\')"` 輸出到 HTML 後,瀏覽器解析屬性值遇到反斜線就斷了,事件根本沒綁上。

**正解**:onclick 參數一律用 HTML 實體單引號 `&#39;`,不要用 `\'`。

```
錯: '<div onclick="_t2(\'名人堂\')">'
對: '<div onclick="_t2(&#39;名人堂&#39;)">'
```

**加強保險**:所有 onclick 會用到的函式明確掛全域 —— `window._fn = _fn;`,避免動態 innerHTML 找不到函式。

## 坑 2:字串接合斷裂導致整段 JS 掛掉

**症狀**:整頁 JS 報 `Invalid or unexpected token`,所有互動失效。

**原因**:用程式插入新段落時,前一行結尾寫成 `+'` 而非 `'+`,字串沒閉合,後面整段被吃掉。

**正解**:多行字串接合,每行固定收尾為 `'+`,下一行固定以 `'` 開頭。改完必驗。

## 坑 3:眼睛看不出語法錯,一定要用 node 驗

**規則:交付任何含 JS 的 HTML 前,先跑語法驗證,通過才交。**

```bash
node -e "
const fs=require('fs');
const h=fs.readFileSync('檔名.html','utf8');
const m=h.match(/<script>([\s\S]*)<\/script>/);
try{ new Function(m[1]); console.log('✓ JS 語法正確'); }
catch(e){ console.log('✗', e.message); }
"
```

要定位到行號時,把 script 抽成 .js 再 `node --check`。

## 坑 4:複雜互動原型不要用即時渲染

**症狀**:大型互動原型即時渲染會卡死/逾時。

**正解**:複雜原型一律**產出 HTML 檔交付下載**,不在對話內即時渲染。好處:可存檔、可重複開、可轉給合夥人或工程師。

## 坑 5:中文檔名可能導致下載失效

「咖」字曾造成檔名顯示錯亂與無法下載。**交付檔名優先用英文小寫加連字號**,中文放在文件標題裡。

## 坑 6:對齊簡報 ≠ 抄簡報底色

簡報的深褐黑底是**投影片展示舞台**,用來襯托白卡。實際 App/後台一律**白底**。
對齊簡報時,對齊的是白卡內部的設計語言(三圓點卡頭、淺灰數據小卡、蜜桃粉強調、奶茶色標籤、深色大按鈕),不是背景色。
