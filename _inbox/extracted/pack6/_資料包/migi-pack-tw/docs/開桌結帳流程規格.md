# MIGI 麻將連鎖 — 開桌結帳流程規格 v1.0

> 每天營運最高頻的核心流程,且直接踩法規紅線(桌面不見現金、全程點數)。
> 設計原則:**全程點數 · 桌面不見現金 · 開桌即扣 · 網咖式超時提醒(不偷扣)**。
> 開桌方式:**櫃台報到 + 雙軌開桌(滿四自動 / 店員手動)**,身分雙軌(報手機 / 掃 LIFF 會員碼)。
> 計費出自創辦人實務拍板。

---

## 1. 兩套計費規則

### 配桌(系統湊桌 · 按人頭)
| 情況 | 收費 |
|---|---|
| 打滿 3 將 | 150 點/人 |
| 中途加入未滿 3 將 | 100 點/人 |
| 遲到、棄賽未滿 3 將 | 照收 150 點/人 |

**邏輯**:佔了系統配好的位子就要付。只有「中途加入」(非自願、半路才進場、本就不可能打滿 3 將)給低消 100;遲到、棄賽是自己責任,照收 150。守住「佔位就付、保護成桌率」。

### 包桌(自己一桌 · 按時間階梯 · 整桌計)
| 時段 | 收費 |
|---|---|
| 0–2 小時 | 400 點/桌 |
| 2–5 小時 | 600 點/桌 |
| 5–24 小時 | 800 點/桌(封頂) |

**邏輯**:不跟陌生人併桌、不限將數、有隱私。封頂 800 對「自帶整團久坐」友善,呼應招團策略。

---

## 2. 扣款邏輯(開桌即扣)

**原則:開桌前先確認條件(配桌/包桌、幾人、預估時段),開桌瞬間就扣,不等收桌。**

### 配桌扣款
| 對象 | 扣款時機 | 金額 |
|---|---|---|
| 開桌時在場的人 | 開桌瞬間 | 扣 150(以打滿 3 將基準) |
| └ 打滿 / 遲到 / 棄賽 | 收桌 | 不退(維持 150) |
| 中途加入的人 | 加入當下 | 扣 100(獨立處理,不經 150 再退) |

> 注意:中途加入者**不是**「先扣 150 再退 50」,而是加入當下直接扣 100。她不在開桌時點,扣款是另一個時間點、另一個費率。

### 包桌扣款
- 開桌前問「打多久」→ 直接扣對應階梯整桌價
- 超時 → 見 §3 超時提醒

---

## 3. 超時提醒(網咖式)

- 時段快到**前 10 分鐘**,系統跳提醒(店員端 + 推播客人)
- 客人決定:
  - **要續** → 補扣升階(2hr→5hr 補 200;5hr→24hr 補 200)
  - **不續** → 在時限內準備收桌
- **不自動偷扣** → 客人有掌控感,呼應「安心」品牌定位

---

## 4. 完整生命週期

```
① 報到(LINE 掃碼/報手機 → 認出會員、餘額、偏好、預約)
      ↓ 選模式
   ┌──────────────┬──────────────┐
   配桌                          包桌
   湊滿4人→指定桌→開桌            先問打多久→開桌
   開桌扣 150/人(在場)           開桌扣階梯價(400/600/800)
   中途加入→扣 100               超時前10分提醒→續(補200)/不續
   收桌:遲到棄賽不退              收桌:依最終階梯
   └──────────────┴──────────────┘
                  ↓
         點數不足?→ 線上儲值(LINE Pay/信用卡)補點再扣
                  ↓
   收桌完成 → 三項自動更新:
     · 消費累積(會員分級:珍奶→焦糖布丁→提拉米蘇)
     · 牌局成績(段位 Elo)
     · 店員業績歸因(成桌獎金)
```

## 4.5 開桌方式:櫃台報到 + 雙軌開桌(實務定案)

### 為什麼在櫃台完成(不用自助掃桌碼)
麻將「湊滿四人才能開」,本來就有「等人到齊」的過程,櫃台是天然的集合/調度中心。店員在櫃台報到的同時就在做配桌撮合、關係經營(業務型店員的價值),人力不是額外負擔,是本就需要的角色。
- 防逃費最穩(沒報到就進不了桌)
- 長輩零障礙(報手機就好,不用學手機)
- 配桌/揪團在櫃台收斂,店員當場撮合

### 報到流程
```
客人陸續到店 → 櫃台報到
  ↓ 店員 POS 開一桌(如 T3)
  ↓ 每來一人,店員逐一確認身分 + 扣點:
      · 報手機 → POS 查出會員,或
      · 出示 LIFF 會員碼 → 店員掃 → 認出會員
      · 確認身分 → 扣點(配桌150/人 · 包桌依時段)
  ↓ 觸發桌子啟動(雙軌,見下)
  ↓ 入座開打 → 鏡頭自動掃牌譜 → 收桌自動扣點/升段
```

### 身分識別雙軌(涵蓋所有客群)
- **熟手機**:出示 LIFF 會員碼,店員掃 → 快
- **不熟手機/長輩**:報手機號,店員查 → 簡單
- 完全不用手機者:店員代開會員(手機+姓名,line_user_id 留空)

### 開桌雙軌(系統處理標準、店員處理例外)
- **軌道一 · 滿四人自動開**:四人都報到扣點完成 → 系統判定滿四 → 桌子自動啟動(標準情況,80%)
- **軌道二 · 店員手動開**:店員按「開桌」鍵,人數由店員判斷 → 啟動。適用:三人先打/等補位/代打/VIP通融/系統誤判需人工(例外情況,20%)
- 精神:系統處理標準、人處理例外,店員保有最終裁量權

### 計費與雙軌的對齊
- 自動開(滿四):配桌扣四人各150;包桌扣整桌(400/600/800)
- 手動開(不滿四):配桌扣在場幾人(中途補到的加入時扣100);包桌一樣扣整桌(按桌不按人)
- 店員手動開時,POS 確認「現在幾人 · 配桌/包桌」→ 系統照規則扣

### 桌子啟動 = 電控連動(分階段)
- **第一階段(開店)**:不接電控,店員確認扣點完成後口頭/手動放行,先把流程跑順
- **第二階段**:接電控(參考摩寶 iSHOP 這類「無人麻將館」的場域電控硬體,或外加智慧插座/繼電器),做到「扣點完成 → 桌子自動啟動」。買一般好桌(東方不敗/雀王/長勝)+ 外加電控,不必買特殊桌
- 進場嚴格(扣點才開)、退場溫和(超時前10分提醒,不硬斷電,呼應安心定位)

### 一氣呵成(關卡只有櫃台報到,之後全自動)
```
報到(櫃台:店員確認身分+扣點)← 唯一人工關卡
  ↓ 四人到齊(自動)or 店員開桌(手動)
桌子自動啟動(電控)← 自動
打牌 → 鏡頭自動掃牌譜 ← 自動
收桌 → 自動扣點結算、自動升段位 ← 自動
```
客人坐下之後什麼都不用管,報到由店員一手包辦。

## 5. 金流鐵則:所有付款先轉點數,無一例外 ⭐

**MIGI 不可破的鐵則:不管是誰、不管付什麼,現金一律先轉成點數存進會員帳戶,再用點數消費。長輩、VIP、老闆的朋友、任何人都一樣,沒有例外。**

```
任何付款(現金 / 刷卡 / LINE Pay)
        ↓
一律先「儲值」成 MIGI 點數(存進會員帳戶)
        ↓
打牌 / 餐飲 / 周邊 一律用點數扣
```

### 為什麼無一例外(這條線守住三件事)
1. **賭博紅線**:現金只停在櫃台換點數,絕不上牌桌。一有「直接付現打牌」的例外,紅線就破。
2. **帳務完整**:所有消費都是點數扣款 → 都有紀錄、進報表、算店員業績。付現走另一套 = 系統裡的幽靈消費,破壞資料完整性。
3. **會員經營**:轉點數就得有會員帳戶 → 消費/來店/牌咖關係才進 CRM,店員才經營得到。

### 唯一的差別是「操作介面」,不是「錢的流向」
- 年輕人:自己用 App/LIFF 儲值
- **長輩/不用 App 的人:店員在櫃台 POS 代為操作**(代開會員、代儲值、代查餘額)。長輩全程不用碰手機,只要「給錢、報手機/姓名、去打牌」。
- 錢的流向完全一樣:**現金 → 點數 → 消費扣點**。

### 對系統的要求
- `members.line_user_id` 必須**允許留空**(長輩會員可能沒 LINE,只有手機+姓名,由店員代開)
- POS 要支援店員「代開會員 / 代儲值 / 代查餘額」
- 金流唯一入口 = 儲值;消費唯一方式 = 扣點。沒有「現場付現直接消費」的路徑。

## 6. 法規守線

- **全程點數,桌面不見現金** = 法規護城河(避免博弈疑慮)
- 結算 = 點數餘額扣減,非現金交易
- 儲值走線上金流(綠界/藍新 + LINE Pay/信用卡)或櫃台現金,皆先轉點數,有完整紀錄
- (連動《可擴張技術基礎建設藍圖》:點數系統的跨店流通與加盟拆帳欄位)

## 7. 系統需求(連動開發)

- **桌狀態機**:空桌 → 開桌(計時/計將中)→ 超時提醒 → 收桌 → 結算 → 空桌
- 每桌記錄:桌號、模式(配桌/包桌)、成員、開始時間、將數/時段、促成店員
- 開桌即扣 → 需即時點數扣款 API(Supabase Edge Function · Dashboard 部署)
- 中途加入、超時補扣 → 獨立扣款事件
- 收桌 → 觸發消費累積 / 成績 / 店員歸因三項更新
- 店員後台「今日缺桌」「我的客人」連動(見《業務型店員與獎金制度》)
